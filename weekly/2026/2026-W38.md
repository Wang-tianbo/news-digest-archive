## 本周主线

本周最强的变化是 agent 产品开始把模型和运行时当作需要治理的生命周期对象，而不是一次性能力发布。OpenAI Learn 提醒 Codex / ChatGPT 用户处理 GPT-5.5 退役迁移，GitHub Copilot 同时预告部分模型退役并暴露成员模型选择可见性，Google Gemini API 继续维护模型 deprecation / shutdown / replacement 表格，这些都把模型版本变成了运维问题。

第二条主线是预算和路由进入组织控制面。Copilot auto model selection 暴露 efficiency / balance / intelligence 三档，Copilot budget increase requests 达到 GA，Qwen Code 把 per-turn token budget、Goal limits、scheduled model routing、ACP child admission 和 workflow provenance 做成稳定功能，说明 agent 的成本、质量、延迟和权限已经开始被产品化管理。

第三条主线是 agent runtime 的可靠性继续加厚。Claude Code 连续围绕 gateway hint headers、MCP 超时 / 重连、Remote Control fork、context compaction、background agent 和 server-side Auto mode classifier 修补长会话边界；Gemini CLI stable 则继续沉淀 OAuth、workspace trust、sandbox、filesystem、tool-output provenance 等安全修复。

第四条主线是交互形态扩展到实时语音和 computer-use。Gemini 3.8 Live / Live Extended Thinking 进入 GA，把 audio-to-audio、异步函数调用、背景推理和 session client updates 组合成 API 产品；开源社区的 `trycua/cua` 则显示 computer-use agent 正在被包装成可安装框架，但安全边界和 benchmark 仍不足以支撑强趋势判断。

## 本周评论与判断

- 基于本周样本的判断：agent 平台的竞争单位正在从“默认模型有多强”变成“模型生命周期 + 自动路由 + 预算审批 + 运行时证据 + 退役迁移”。这比单个模型 headline 更接近企业真实采用的问题。
- GitHub、Qwen、Anthropic、Google 和 OpenAI 的更新虽然入口不同，但都在回答同一组问题：谁决定用哪个模型，预算如何申请，模式如何自动分类，长会话如何恢复，模型退役前如何迁移，异常行为如何披露。
- 本周最值得加权的是 `budget_and_route_governance`。Copilot 的 route tier 和预算申请，Qwen 的 token budget / scheduled route，以及 Claude 的 server-side Auto mode classifier 共同说明“自动选择”正在成为平台控制权，而不是单纯 UX 优化。
- `external_verification` 没有消失，但形态发生转移：Vercel AI SDK 的 evaluation model / tool discovery、OpenAI misalignment reporting framework、ScienceBuddy 的 execution evidence、social harness 和 JustFit 的状态管理，都在把“完成与可靠”拆成可积累、可复查的证据对象。
- 本周应降权的是只有版本号、没有行为证据的 release cadence。Codex alpha 和 Gemini nightly 仍值得观察，但不能从版本发布本身推出能力变化。

### AI 研究前沿

- **多 agent 协作需要社会层 harness。** [Agentic Societies Need a Social Harness](https://arxiv.org/abs/2609.17527) 指出多 agent 跨信任边界协作时，个人 harness 不足以约束通信漏洞和恶意 / 故障 agent。这直接解释 Qwen cross-session messaging、ACP child admission 和 workflow correlation 为什么需要关系级治理。
- **科研 agent 的改进正在变成 harness + evidence + model 的闭环。** [ScienceBuddy](https://arxiv.org/abs/2609.17523) 把 interactive scientific research workspace、执行证据、rubric、harness 迭代和模型训练放进同一循环。它与 Vercel evaluation model、Claude / Qwen workflow telemetry 同向。
- **本地长上下文 agent 的瓶颈是状态管理。** [JustFit](https://arxiv.org/abs/2609.17475) 用 KVExec、PhaseSwap 和 StateTrans 讨论 24 GiB MacBook 上的长上下文 serving。即使结果仍待复现，它也提醒本地 coding agent 的竞争点会从“能跑模型”转向“能保存和切换状态”。
- **工具和计划安全继续是可验证问题。** Plan injection、native skill routing、benchmark artifact dependency graph 和 closed-loop repair 一组研究都指向同一件事：agent 不应只靠 prompt stuffing 和单次 pass/fail，而需要工具边界、计划验证、中间产物依赖和局部修复。
