#### 1. Anthropic 发布 Claude 形式化费马大定理结果，给出端到端 Lean 机检证明

- 事实：Anthropic 在 2026-09-04 发布 “Formalizing Fermat's Last Theorem”，称其分享了第一个完整的、计算机检查过的费马大定理证明；Claude 在 11 天内大体自主地用 Lean 编写证明，并完成 29,500 个中间定理，证明仓库公开在 GitHub。

- 我的判断：这会抬高“AI 科学发现”叙事的证据门槛。真正有价值的不只是 Claude 能写多少 Lean，而是模型输出能否被 proof checker、代码仓库和复查流程承接。
- 来源：[Anthropic - Formalizing Fermat's Last Theorem](https://www.anthropic.com/research/formalizing-fermats-last-theorem)，[Proof repository](https://github.com/anthropics/fermats-last-theorem)

- 事实：GitHub 在 2026-09-04 发布 Project HydraFusion。官方称它在运行时为 coding task 选择 single、cascade 或 critique 等执行模式，在 TerminalBench 2.1、DeepSWE 和 CheckpointBench 的离线评估中接近或超过 Opus 5 基线，并降低估算成本；目前通过 Copilot CLI 的 `/experimental` 提供 research preview。

## AI 研究前沿

### 1. EEBench：用仿真检查 AI 设计电路是否真的工作

- 类型：benchmark
- 研究问题：模型能在 KiCad 或电路任务中看起来会画板，但生成的电路是否满足电气约束、BOM、容差和仿真检查，仍需要可复查评测。
- 核心思路：EEBench V1 使用 `atopile` 的 declarative code 让 agent 修改组件、连接和约束，再通过构建电路图、BOM、SPICE simulation 和 design checks 给出确定性评分；文章说明 V1 覆盖 analog / digital design through simulation，但还不覆盖完整 layout、制造和 bring-up。
- 为什么可能影响未来：如果电路设计 benchmark 能稳定运行，AI for engineering 会从“生成图形 / 代码”推进到“物理约束下的可验证设计”。
- 局限 / 待验证点：EEBench 由 atopile 团队构建并资助；当前只覆盖部分 circuit problems 和 simulation，不能外推到完整硬件产品。
- 研究成熟度：早期 benchmark
- 可复现状态：公开说明与应用入口可查；本次未复跑
- 原文链接：[EEBench - Can AI design circuit boards yet?](https://eebench.org/blog/can-ai-design-circuit-boards-yet/)
- 权威解读：暂无
- 我的判断：它和 Anthropic FLT 的共同点是“让 AI 输出进入外部 checker”。这比又一个主观 demo 更值得长期追踪。

### 2. One-shot OPD 论文挑战“后训练一定要大量任务数据”的直觉

- 类型：论文
- 研究问题：on-policy distillation 依赖 student rollouts 和 teacher token-level supervision，但训练数据本身对 OPD 增益到底有多关键仍不清楚。
- 核心思路：论文在 data-minimal limit 下训练单个 query，报告 one-shot OPD 可以持续改进数百步，并恢复大部分 full-data OPD 增益；作者用 state coverage 解释现象，称单个 query 的 rollouts 已覆盖 full-data OPD 访问状态的 71.5%，16 个语义多样 query 可到 98.9%，并将 full-data 训练效果追平。
- 为什么可能影响未来：如果结果成立，frontier post-training 的瓶颈可能部分从“收集更多任务”转到“提高 OPD step efficiency、状态覆盖和 teacher signal 吸收效率”。
- 局限 / 待验证点：这是 arXiv 早期论文；结论依赖作者实验设置、任务域和模型族，本次未复跑。
- 研究成熟度：早期论文
- 可复现状态：论文原文可查；本次未复跑
- 原文链接：[arXiv:2609.04172v1](https://arxiv.org/abs/2609.04172v1)
- 权威解读：暂无
- 我的判断：它能和 HydraFusion / Portal 的调度问题形成互补：模型后训练和 runtime 调度都在寻找“少量高价值信号如何覆盖大量状态”。
