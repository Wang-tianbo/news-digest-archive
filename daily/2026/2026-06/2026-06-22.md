## 主线判断

本期最值得记住的不是新模型，而是 AI 编程代理和本地推理运行时继续进入“边界工程”阶段。Qwen Code `0.18.5` 把大量改动集中在路径、端口、环境变量、OAuth、ACP、Web Shell、MCP resources 等容易造成越权或不确定行为的边界上；Codex `0.142` alpha 则继续围绕远程执行、上下文谱系和 code-mode runtime 重构推进；llama.cpp 的多次 release 继续把本地模型服务做得更接近可观测、可批处理、可结构化输出的生产服务。

## 今日评论与判断

基于本期样本的判断：AI coding agent 的竞争正在从“能不能写代码”进一步转向“能不能被组织安全地长时间运行”。Qwen Code 和 Codex 的更新都指向同一类问题：路径边界、权限 opt-in、远程执行意图、上下文 lineage、MCP / prompt / resource 注入，这些不是炫技功能，而是让 agent 可以被持续接入真实工程环境的基础设施。

Qwen Code 本期信号偏强，原因不是单个大功能，而是 stable release 中一次性收敛了大量边界条件。对于中国模型公司生态来说，这类工具链工程化比单纯发布模型 demo 更值得跟踪，因为它决定模型能否变成开发者每天使用的工作流入口。

Codex 的 `0.142` alpha 仍然是预发布信号，不能过度解读为最终产品形态。但 compare 记录显示，OpenAI 正在处理远程执行、上下文压缩提醒、session ownership、transport-neutral runtime types 等底层问题，说明 Codex 的重点仍是把 agent runtime 做成可迁移、可远程、可恢复的执行系统。

llama.cpp 的连续 release 继续证明开源本地推理层正在补齐“服务化”细节。模型加载进度、batch 构造、speculative decoding、Jinja / grammar 支持这些更新单看都很工程，但合在一起会直接影响本地部署、私有化推理和轻量 agent server 的可用性。

## 今日最重要的 3 条更新

### 1. Qwen Code `0.18.5` 发布：权限、路径、端口、ACP、MCP resources 继续收紧

- 发生了什么：Qwen Code 在 2026-06-21 发布 `v0.18.5` stable，并在 2026-06-22 08:52:42 Asia/Shanghai 发布 `v0.18.5-nightly.20260622.6bc3f853e`。`0.18.5` release notes 包含 plan mode prompt opt-in、shell directory workspace boundary、LSP socket port 校验、环境变量严格解析、ACP glob / file read window 校验、Web Shell 文件发送、OAuth token response 校验、MCP resources 与 prompt surfaced 等多项改动。
- 为什么重要：这是一组典型的 agent runtime hardening 更新，重点不是新模型能力，而是减少自动化开发工具在文件系统、端口、插件、远程输入、MCP 资源等边界上的不可控行为。它延续了 2026-06-21 日报中 Qwen Code `0.18.4` 的方向，但 `0.18.5` 更像一次集中清理与策略收口。
- 来源：[Qwen Code Release `v0.18.5`](https://github.com/QwenLM/qwen-code/releases/tag/v0.18.5)、[Qwen Code Nightly `v0.18.5-nightly.20260622.6bc3f853e`](https://github.com/QwenLM/qwen-code/releases/tag/v0.18.5-nightly.20260622.6bc3f853e)、[Qwen Code compare `v0.18.4...v0.18.5`](https://github.com/QwenLM/qwen-code/compare/v0.18.4...v0.18.5)

### 2. Codex `0.142.0` alpha 连发：远程执行、上下文 lineage、code-mode runtime 继续重构

- 发生了什么：OpenAI Codex 在严格窗口内发布 `rust-v0.142.0-alpha.8`、`alpha.9`、`alpha.10`。从 `rust-v0.142.0-alpha.7...alpha.10` 的 compare 看，相关 commits 包括允许 task / MCP startup 期间 resume 与 settings 命令、增加 context window lineage IDs、原型化 `mcp_history` thread hint injection、可配置 token budget compaction reminder、把 sandbox intent 传递给 remote exec servers，以及 code-mode transport-neutral runtime types、session ownership、terminal state 等重构。
- 为什么重要：这些更新显示 Codex 正在把 coding agent 从单次本地 CLI 操作推向更复杂的远程执行与可恢复 session 模型。对开发者工作流而言，关键变量不只是模型本身，而是 agent 在长任务、远程 shell、上下文压缩、MCP 注入和状态恢复中的可靠性。
- 来源：[Codex Release `rust-v0.142.0-alpha.8`](https://github.com/openai/codex/releases/tag/rust-v0.142.0-alpha.8)、[Codex Release `rust-v0.142.0-alpha.9`](https://github.com/openai/codex/releases/tag/rust-v0.142.0-alpha.9)、[Codex Release `rust-v0.142.0-alpha.10`](https://github.com/openai/codex/releases/tag/rust-v0.142.0-alpha.10)、[Codex compare `rust-v0.142.0-alpha.7...rust-v0.142.0-alpha.10`](https://github.com/openai/codex/compare/rust-v0.142.0-alpha.7...rust-v0.142.0-alpha.10)

### 3. llama.cpp `b9745` 至 `b9754` 连续发布：本地推理服务层继续补齐可观测性与结构化输出

- 发生了什么：llama.cpp 在窗口内连续发布 `b9745`、`b9747`、`b9748`、`b9750`、`b9752`、`b9753`、`b9754` 等版本，覆盖 Step3.5 / 3.7 flash MTP3 speculative 支持、`/models/sse` 实时模型加载进度、server schema `verbose` 字段、Jinja `call` statement、server batch construction 重构、加载 speculative models 的 progress stages，以及更严格 grammar generation 的 PEG parser。
- 为什么重要：这些都是让本地推理运行时更像生产 API server 的工程能力。对企业私有化、边缘部署和本地 coding agent 来说，加载进度、batch 调度、schema / grammar、模板兼容和 speculative decoding 会直接影响稳定性、延迟和可控输出。
- 来源：[llama.cpp Release `b9745`](https://github.com/ggml-org/llama.cpp/releases/tag/b9745)、[llama.cpp Release `b9747`](https://github.com/ggml-org/llama.cpp/releases/tag/b9747)、[llama.cpp Release `b9752`](https://github.com/ggml-org/llama.cpp/releases/tag/b9752)、[llama.cpp Release `b9754`](https://github.com/ggml-org/llama.cpp/releases/tag/b9754)
