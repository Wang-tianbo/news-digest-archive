# 日报写作规范

## 1. 时间窗

- 每篇日报覆盖前一日 09:00 到当日 09:00，时区为 Asia/Shanghai
- 标题和正文都使用绝对日期，例如 `2026-05-13`

## 2. 来源要求

- 优先使用官方来源
- 如果引用媒体报道，尽量补上一手来源
- 每条重要信息都保留可点击来源链接

## 3. 选题方法

优先选以下内容：

- 新模型、新产品、新能力发布
- 官方博客、研究、技术文章
- AI 编程代理的重要动作
- GitHub 上快速升温的 AI 开源项目
- 对商业格局、开发者工作流或技术路线有明显影响的事件

降低优先级的内容：

- 重复转述的二手报道
- 没有原始来源的流言
- 只有流量、没有信息增量的话题

## 4. 写作要求

- 先写结论，再写事实
- 每条信息尽量控制在 3 段以内
- 每篇报告必须包含单独的评论 / 判断模块
- 每条信息至少包含：
  - 发生了什么
  - 为什么重要
  - 来源链接

评论 / 判断模块建议回答：

- 今天真正值得记住的主线是什么
- 哪家公司或哪条产品线在加速
- 哪些变化可能只是噪声，哪些是趋势
- 接下来 1 周、1 个月值得继续跟踪什么

## 5. 推荐栏目

- `主线判断`
- `今日评论与判断`
- `今日最重要的 3-5 条更新`
- `中美大模型`
- `AI 编程代理`
- `官方博客 / 研究 / 发布`
- `GitHub 热门项目`
- `值得继续跟踪`
- `参考来源`

## 6. 口径要求

- 事实和个人判断分开
- 评论必须建立在当天事实之上，不能写成空泛感想
- 如果信息存在不确定性，要明确写出“尚待验证”
- 如果某家公司当天没有高价值更新，不强行凑数
- 报告目标是高信噪比，不是信息全收录

## 7. 文件规范

- 路径：`daily/YYYY/YYYY-MM/YYYY-MM-DD.md`
- 标题：`# AI 日报 - YYYY-MM-DD`
- commit message：`docs: add ai digest for YYYY-MM-DD`
- 周报路径：`weekly/YYYY/YYYY-Www.md`
- 月报路径：`monthly/YYYY/YYYY-MM.md`
- 年报路径：`yearly/YYYY/YYYY.md`

## 8. 长期建议

- 日报控制在 8-15 条重点信息
- 周末仍可生成日报，但允许内容更短
- 每周补一篇周报，聚合当周主线与重复信号
- 月报要强调阶段性格局变化、公司节奏和主题演进
- 年报要强调全年拐点、胜负手、方法论变化和持续判断修正
