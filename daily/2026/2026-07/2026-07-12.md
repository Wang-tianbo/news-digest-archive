#### 1. vLLM `v0.25.0`：Model Runner V2 成为 dense model 默认路径，旧 PagedAttention 被移除

- 发生了什么：vLLM 发布 [`v0.25.0`](https://github.com/vllm-project/vllm/releases/tag/v0.25.0)，官方 release notes 记录该版本包含 558 个 commits、232 位贡献者。重点包括 Model Runner V2 成为所有 dense models 默认执行路径，继续补 quantized model、EVS、realtime embeddings、Mamba hybrid prefix caching 和 multimodal 能力；同时旧 PagedAttention 实现被移除。
- 为什么重要：这是推理服务框架的结构性更新。vLLM 不只是“又发版”，而是在把 V1 / MRv2 后端标准化，减少旧路径，同时为新模型形态、实时 embeddings 和多模态 serving 留出统一执行路径。
- 证据口径：vLLM 官方 GitHub Release。
- 来源：[vLLM v0.25.0](https://github.com/vllm-project/vllm/releases/tag/v0.25.0)

#### 2. Pydantic AI `v2.9.0` / `v1.107.1`：修补 AG-UI dangling tool-call 清洗风险

- 发生了什么：Pydantic AI 发布 [`v2.9.0`](https://github.com/pydantic/pydantic-ai/releases/tag/v2.9.0) 和 [`v1.107.1`](https://github.com/pydantic/pydantic-ai/releases/tag/v1.107.1)，披露并修补中等严重度安全问题 [`GHSA-jpr8-2v3g-wgf9`](https://github.com/pydantic/pydantic-ai/security/advisories/GHSA-jpr8-2v3g-wgf9)。问题涉及 AG-UI serving path 中 `UIAdapter.sanitize_messages` 对 dangling tool-call strip 的处理，可能在特定版本范围内造成权限检查边界问题。
- 为什么重要：agent UI 的消息清洗不再是前端细节，而是权限和安全边界。随着工具调用、AG-UI、桌面 agent 和多端会话进入真实应用，message sanitization、tool-call lifecycle 和权限检查会成为框架级风险面。
- 证据口径：Pydantic AI 官方 GitHub Release 与官方安全公告。
- 来源：[Pydantic AI v2.9.0](https://github.com/pydantic/pydantic-ai/releases/tag/v2.9.0)、[Pydantic AI v1.107.1](https://github.com/pydantic/pydantic-ai/releases/tag/v1.107.1)、[GHSA-jpr8-2v3g-wgf9](https://github.com/pydantic/pydantic-ai/security/advisories/GHSA-jpr8-2v3g-wgf9)

#### 3. Ollama `v0.32.0-rc0`：本地模型工具链开始显式加入 agent UI 和旧 agent model 警告

- 发生了什么：Ollama 发布 [`v0.32.0-rc0`](https://github.com/ollama/ollama/releases/tag/v0.32.0-rc0)，变更包括为 Qwen3.5 / Next 选择 parser 和 renderer、启动时对旧 agent models 给出警告，以及加入 agent UI。

#### 4. Transformers `v5.13.1` 与 llama.cpp 连续修复：serving / 本地推理兼容层继续补边界

- 发生了什么：Hugging Face Transformers 发布 [`v5.13.1`](https://github.com/huggingface/transformers/releases/tag/v5.13.1)，release notes 明确该 patch focused on enabling Transformers for the latest vLLM release，并修复 custom model layer type remap、custom code 线性层名称和 `_LazyAutoMapping.register` 字符串 key 等问题。llama.cpp 在本窗口发布 [`b9967`](https://github.com/ggml-org/llama.cpp/releases/tag/b9967)、[`b9966`](https://github.com/ggml-org/llama.cpp/releases/tag/b9966)、[`b9965`](https://github.com/ggml-org/llama.cpp/releases/tag/b9965)、[`b9964`](https://github.com/ggml-org/llama.cpp/releases/tag/b9964)，涉及 server null sampling params、tensor-split regex 性能、Hexagon small tensor ARGSORT 和 spec model duplicate download 等修复。
- 为什么重要：这组更新说明模型生态的真实瓶颈常常在兼容层和边界参数。Transformers 和 vLLM 的互相适配、本地 server 对 nullable sampling params 的容忍、tensor split 性能，都会影响模型能否稳定进入生产或本地 agent workflow。

## AI 研究前沿

### UniClawBench：面向真实工具和动态环境的 proactive agents 评测

- 类型：论文 / benchmark / 开源实现
- 日期：2026-07-10 01:59 Asia/Shanghai（补充范围）
- 研究问题：现有 agent benchmark 往往依赖 sandbox 或单轮评测，难以定位 proactive agents 在真实工具、动态环境、多轮反馈和跨平台任务中的失败原因。
- 核心思路：论文 [UniClawBench: A Universal Benchmark for Proactive Agents on Real-World Tasks](https://arxiv.org/abs/2607.08768) 提出 capability-driven benchmark，围绕 Skill Usage、Exploration、Long-Context Reasoning、Multimodal Understanding、Cross-Platform Coordination 五类能力设计 400 个中英双语真实任务，并在 live Docker containers 中用 step-by-step completion checkpoints 评测。作者还设计 executor agent、hidden supervisor agent 和 user agent 的闭环评估策略，减少评分标准泄漏。
- 为什么可能影响未来：Codex、Claude Code、Qwen Code、ChatGPT Work 和 Copilot sessions 都在走向长任务、跨工具和多端接管。UniClawBench 的价值不在又一个总分榜，而在把 agent 失败拆成模型能力与 framework 设计的共同结果。
- 局限 / 待验证点：论文为早期 benchmark；本次未运行代码，也未验证任务覆盖是否能代表真实企业开发、办公和浏览器场景。Docker live eval 的复现实操成本也需要观察。
- 研究成熟度：早期论文 / benchmark。
- 可复现状态：论文公开；摘要声明 benchmark 和 code 公开，仓库链接需后续复核完整可用性。
- 原文链接：[arXiv 2607.08768](https://arxiv.org/abs/2607.08768)
- 权威解读：暂无。
- 我的判断：这条适合进入 agent eval 长期台账。未来判断 coding agent 不能只看 SWE-bench，还要看跨平台、长上下文、多模态和真实工具协调能力。
