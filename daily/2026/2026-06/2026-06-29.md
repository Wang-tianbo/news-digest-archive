## 今日最重要的 4 条更新

### 1. Qwen Code `0.19.3` 发布，daemon、Web Shell、skills、telemetry 与 WebFetch 安全进入 stable

- 发生了什么：Qwen Code 于 `2026-06-28 14:12:31` Asia/Shanghai 发布 [v0.19.3](https://github.com/QwenLM/qwen-code/releases/tag/v0.19.3)。Release notes 包括：WebFetch JSON fallback、OpenAI pipeline streaming inactivity timeout 与 `QWEN_STREAM_IDLE_TIMEOUT_MS`、daemon workspace voice / control APIs、skill usage stats、auto-generated skills 持久化前确认、Web Shell loading state 和 streamed turn transcript 处理、Excel-style markdown tables、provider id 到 SDK protocol 的 `providerProtocol` 映射、telemetry sensitive span attribute limit 配置、voice dictation keyterms file、拒绝 WebFetch userinfo URLs、MCP servers live reconciliation、single session status query、bundled extension creator skill、`@extension` mention autocomplete、CUA driver opt-in relative coordinates 等。
- 为什么重要：这是中国侧 AI coding agent 最稳定的严格窗口信号。它把前几天 nightly 中分散出现的 runtime、Web Shell、skills、telemetry、多 provider 与安全校验能力打包进 stable release，说明 Qwen Code 继续把重点放在执行层和可部署性，而不是只追模型 headline。
- 来源：[Qwen Code Release `v0.19.3`](https://github.com/QwenLM/qwen-code/releases/tag/v0.19.3)

### 2. Gemini CLI nightly 补 sensitive path blocklist 与 VS Code HITL 安全

- 发生了什么：Google Gemini CLI 于 `2026-06-28 09:45:53` Asia/Shanghai 发布 [v0.51.0-nightly.20260628.gae0a3aa7b](https://github.com/google-gemini/gemini-cli/releases/tag/v0.51.0-nightly.20260628.gae0a3aa7b)。Release notes 只有一条高价值安全项：enforce case-insensitive sensitive path blocklist and VS Code HITL。
- 为什么重要：这是小版本，但方向明确。coding agent 在 IDE / CLI 内执行时，路径大小写、敏感目录和 human-in-the-loop 确认都可能成为真实安全边界；Google 继续把 Gemini CLI 的工程重心放在工具安装、路径保护、信任覆盖和企业环境可控性上。
- 来源：[Gemini CLI Release `v0.51.0-nightly.20260628.gae0a3aa7b`](https://github.com/google-gemini/gemini-cli/releases/tag/v0.51.0-nightly.20260628.gae0a3aa7b)

### 3. Cline `4.0.1` 回滚 stable VS Code extension，SDK migration 暂不继续压到 stable

- 发生了什么：Cline 于 `2026-06-28 10:48` Asia/Shanghai 发布 [v4.0.1](https://github.com/cline/cline/releases/tag/v4.0.1)。官方 release notes 称，该版本把 stable VS Code extension 回滚到 SDK migration 前的 `3.89.2` extension codebase，以解决 `4.0.0` 报告的 regressions；SDK migration 工作继续在 `main` 分支推进。
- 为什么重要：这是一条 agent 工具稳定性信号。Cline 没有硬推一次大型 SDK migration，而是把 stable 用户拉回已知更稳的代码线，说明 AI 编程扩展的升级风险正在被当作产品主线问题处理。
- 来源：[Cline Release `v4.0.1`](https://github.com/cline/cline/releases/tag/v4.0.1)

### 4. llama.cpp 连续补 reasoning 保留、MiniCPM5 tool-call parser、DFlash 与离线下载检查

- 发生了什么：llama.cpp 在本窗口发布多个版本，其中 [b9837](https://github.com/ggml-org/llama.cpp/releases/tag/b9837) 增加 Jinja / chat `--reasoning-preserve` flag，[b9833](https://github.com/ggml-org/llama.cpp/releases/tag/b9833) 实现 MiniCPM5 tool-call parser，[b9831](https://github.com/ggml-org/llama.cpp/releases/tag/b9831) 增加 DFlash v2 support 与 per-layer sliding window attention，[b9830](https://github.com/ggml-org/llama.cpp/releases/tag/b9830) 让 `llama download` 支持 `--offline`，可检查模型是否已缓存且可服务，同时修复 URL-task callback 的潜在 use-after-free；[b9835](https://github.com/ggml-org/llama.cpp/releases/tag/b9835) 修复 single-model mode 下 stop 与 reasoning skip。
- 为什么重要：这些都是底层兼容性和 serving 体验更新。reasoning 保留、tool-call parser、attention spec、离线缓存检查和 UI 行为，会影响本地模型作为 coding agent / 私有 agent backend 时的上下文语义、工具调用格式和无网络环境可运维性。
- 来源：[llama.cpp `b9837`](https://github.com/ggml-org/llama.cpp/releases/tag/b9837)、[llama.cpp `b9833`](https://github.com/ggml-org/llama.cpp/releases/tag/b9833)、[llama.cpp `b9831`](https://github.com/ggml-org/llama.cpp/releases/tag/b9831)、[llama.cpp `b9830`](https://github.com/ggml-org/llama.cpp/releases/tag/b9830)、[llama.cpp `b9835`](https://github.com/ggml-org/llama.cpp/releases/tag/b9835)
