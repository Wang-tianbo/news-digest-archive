## 本周主线

本周 AI 主线继续从“谁发了更强模型”转向“强模型进入真实工作流后，运行时、路由、评测和治理怎么接住”。Claude Code、Codex、GitHub Copilot、Qwen Code、Kimi Code、Pydantic AI、Vercel AI SDK、Ollama 和 SGLang 的连续更新都在补同一类底座：权限、沙箱、工作树隔离、网络审批、工具调用 ID、成本池、provider 差异、多模型路由、CI / PR 状态和本地推理适配。

模型发布仍然重要，但本周更像“模型到工具分发”的验证周。Anthropic 发布 Claude Opus 5 并迅速进入 GitHub Copilot 线索；Kimi K3 继续通过 Kimi Code、API、开权重计划和海外开源模型讨论扩散；Black Forest Labs 的 FLUX 3 / FLUX-mimic 把多模态生成拉向 world model / action model 叙事。它们的共同点是：模型本身只是起点，真正的信号强弱取决于能否进入开发者工具、agent 框架、推理底座和可复查评测。

中国侧最强连续样本仍是工程工具。Qwen Code 从 `v0.20` 到 `v0.21`，围绕 WebShell、autofix、worktree isolation、workspace Channel、CI evidence、PR 面板、Goal v3、daemon transport 和 MCP OAuth 持续补团队运行时；Kimi Code 则在 MCP timeout、reasoning 字段兼容、web search / fetch 和 subagent model binding 上推进。Cherry Studio v2、OpenWorker、LobeHub 和 StaffDeck 也显示中文桌面 / 数字员工工作台正在从多模型聊天变成本地 agent shell。

研究前沿与产品事实高度同频。OpenAI / Hugging Face eval 安全事件把评测平台本身推入威胁模型；OpenAI long-horizon safety 讨论长任务模型的过程级监控；DocOps、DataFlow-Harness、OpenForgeRL、FLUX 3 和 FLUX-mimic 分别指向文档工件、数据流水线、真实 harness RL、多模态世界模型和动作预测。研究信号不再只是榜单，而是在回答 agent 如何被训练、评测、隔离和接入真实环境。

## 本周评论与判断

基于本周已存档样本的判断，`agent_runtime_governance` 仍是最高置信主线，但它的内涵比 W29 更宽。本周不只是 Claude Code / Qwen Code 修权限和工作树，Codex 加入 thread history、跨工具导入、Bedrock / realtime 与网络审批 hardening，GitHub Copilot 加入 AI credit pools、impact dashboard、Gemini 3.6 Flash 和 Opus 5，Pydantic AI / Vercel AI SDK 修 provider、tool-call、durability、approval HMAC 与 stream 边界。agent 运行时正在变成组织控制面，而不是 CLI 小功能集合。

第二个判断是，多模型路由开始从“模型下拉框”进入 workflow 阶段。Cursor Router、GitHub Copilot 接入 Gemini 3.6 Flash / Opus 5、Copilot CLI 的 plan-mode 专用模型、Kimi Code subagent secondary-model bindings、Pydantic AI 的跨 provider 抽象都说明：planning、editing、review、web access、local inference、high-risk vertical task 未来会被分配到不同模型、价格层和权限层。

第三个判断是，评测安全本周从研究议题变成主线风险。OpenAI / Hugging Face 事件提醒：benchmark、dataset、模型 artifact、eval runner 和 token scope 本身都可能成为攻击面。它与 Claude Code 的 transcript / MCP output 修复、Qwen Code 的 CI evidence 外移、Codex 的 network approval hardening、OpenForgeRL 的 harness rollout 设计共同证明，eval 和 training harness 也必须按生产系统治理。

第四个判断是，桌面 agent 重新升温，但需要严格区分社区热度与可用性。OpenWorker、Cherry Studio v2、LobeHub、StaffDeck、OpenAI Presence、Cursor in Slack 和 Qwen WebShell 共同说明 agent 入口正在贴近本地文件、终端、Slack、Jira、GitHub、日历、邮箱和知识库。真正值得跟踪的是 approval gate、secret storage、connector 权限、失败恢复、审计和真实跨工具任务成功率，而不是 stars 或界面形态。

- `cost_aware_agent_evaluation` 被延续。OpenAI enterprise scorecard、GitHub AI credit pools / credit visibility、Copilot impact dashboard、Pydantic cache / provider 字段、Copilot plan-mode 模型选择都在把成本与产出放入同一治理口径。

- `agent_evaluation_methodology` 被强化。OpenAI / Hugging Face eval 事件、OpenAI long-horizon safety、DataFlow-Harness、DocOps、OpenForgeRL 都把 agent 评测从成功率扩展到安全、工件、环境和训练 harness。

### 上周判断哪些被修正

- `agent_evaluation_methodology` 需要拆出两个子议题：`eval_harness_security` 和 `harness_native_agent_training`。前者关注不可信 artifact、token、network、secret scanning 和 sandbox；后者关注 Claude Code / Codex 类复杂 harness 如何进入 RL / rollout。
- `frontier_model_distribution` 不能只看一个旗舰模型。Opus 5、Kimi K3、FLUX 3 代表三种不同分发路径：开发者工具默认值、开权重 / coding-agent 入口、多模态世界模型 / action model。它们不能用同一成熟度判断。
- `workspace_runtime` 应从候选升格为长期议题，但要拆清楚桌面个人工作台、团队协作入口和平台原生 agent 工件三条子线。
- `open_inference_runtime` 本周更适合并入 `agent_runtime_infrastructure` 观察。Ollama、SGLang、Pydantic AI、Vercel AI SDK 的共同问题是模型进入 agent 工作流后的 provider / serving / tool / local runtime 适配，而不只是推理框架本身。

### 本周新增判断

- `multi_model_agent_routing` 值得进入候选台账。Cursor Router、Copilot 多模型、Copilot CLI plan-mode 模型、Kimi Code subagent model binding 和 Pydantic provider 抽象共同说明，agent workflow 会把模型选择拆到任务阶段。
- `eval_harness_security` 值得正式升格。OpenAI / Hugging Face 事件不是单点事故，而是 AI eval、agent benchmark 和安全研究都会遇到的系统性风险。
- `local_agent_workspace` 值得短期升温观察。OpenWorker、Cherry Studio v2、LobeHub、Ollama 与 Qwen / Kimi Code 表明本地 agent shell、订阅复用、本地推理和 connector 审批会成为重要入口。
- `high_risk_vertical_ai_governance` 开始值得跟踪。Health in ChatGPT 把健康数据、记忆、训练排除和专业责任边界做成产品能力，这会外溢到金融、法律、企业知识库和 coding-agent secret handling。
