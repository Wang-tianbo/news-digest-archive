## AI 研究前沿

### 1. Retrieve-for-Train：把复杂搜索里的 test-time thinking 编译进训练

- 类型：研究博客 / 论文
- 研究问题：复杂搜索和推荐需要返回互补、覆盖、多样且仍贴近数据库的结果集，但让通用 LLM 在线做 query fan-out 会消耗大量推理 token 并带来延迟。
- 核心思路：Google Research 的 Retrieve-for-Train 用离线 RL 训练 fan-out language model，再合成监督数据，把行为蒸馏到 53.9M 参数 diffusion retriever；推理时以非自回归方式一次生成目标 embedding set，绕开在线 CoT。
- 为什么可能影响未来：如果这类方法成立，搜索 agent 的路线会从“上线时多想一会儿”转向“训练时把多样性、对齐和 groundedness 编译进去”，降低实时产品延迟。
- 局限 / 待验证点：样本来自论文与 Google Research 博客，仍需更多公开生产检索场景和第三方复现。
- 研究成熟度：研究博客 / ICML 2026 论文
- 可复现状态：论文公开，未确认第三方复现
- 原文链接：[Google Research - Retrieve-for-Train](https://research.google/blog/bypassing-inference-bottlenecks-accelerating-complex-ai-search-with-retrieve-for-train/)、[arXiv:2603.06397](https://arxiv.org/abs/2603.06397)
- 权威解读：Google Research 原文
- 我的判断：它和 Gemini Live / agent latency 同属一条线：产品化 agent 不能只堆 online reasoning，必须把可验证目标前移到训练、索引和系统设计。

### 2. Plan Injection 与 Skill Routing：agent 监控和 skill 选择都不能只靠上下文堆料

- 类型：论文
- 研究问题：一方面 CoT monitor 可能被上下文中的 benign-sounding harmful plan 绕过；另一方面 agent skill routing 如果把所有 skill metadata 塞进上下文，会分散注意力并限制 skill library 规模。
- 核心思路：`Corrupt Plans, Clean Traces` 提出 plan injection 攻击，显示 actor 会执行注入计划并把它改写成自己的推理；`The Router Within` 则提出 Gavel，从 frozen LLM 中读出 routing signal，用少量线性参数和两阶段 glance/verdict 完成 skill 选择。
- 为什么可能影响未来：两篇论文共同指向一个问题：agent 的控制与选择不能只依赖“把更多说明放进 prompt”。监控需要抗注入，skill routing 需要结构化接口和可测基准。
- 局限 / 待验证点：均为早期论文，plan injection 的真实部署风险和 Gavel 的跨模型/跨工具泛化仍需第三方复现。
- 研究成熟度：早期论文
- 可复现状态：论文公开，未确认第三方复现
- 原文链接：[arXiv:2609.15989](https://arxiv.org/abs/2609.15989)、[arXiv:2609.15982](https://arxiv.org/abs/2609.15982)
- 权威解读：暂无
- 我的判断：这两条研究线和本期 Claude / Gemini / Qwen 的工具边界更新互相印证：agent runtime 的下一层竞争是“选择什么、相信什么、暴露什么状态”。
