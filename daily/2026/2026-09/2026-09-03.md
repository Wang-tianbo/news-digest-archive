#### 3. GitHub Copilot code review public preview 支持在管理员授权后 approve PR

- 事实：GitHub 在 2026-09-01 的 changelog 中宣布，Copilot code review 现在会在 overview comment 中给出 approval assessment；管理员可在 enterprise、organization 或 repository 层启用 Copilot approval。启用后，Copilot 的 approval 可计入 required approvals，新 commit 推送后 approval 会像人工 reviewer 一样失效；管理员还可以配置 Copilot 允许 approval 的文件路径。

## AI 研究前沿

### 1. Efficient SWE Agent Benchmarking：用 trajectory-aware 评测降低 SWE agent benchmark 成本

- 类型：论文
- 研究问题：真实软件工程 agent benchmark 需要多步探索、修改和测试，完整评测成本高；只看 pass/fail 或静态语义的代表子集选择会丢掉 agent 的求解过程。
- 核心思路：论文提出 PTA-IRT，把历史执行轨迹中的过程证据，例如探索上下文、尝试编辑和 solving paths，作为 privileged information，用于 calibration subset selection 和 ability estimation；在低 calibration budget 下恢复分数和排名。
- 为什么可能影响未来：如果 trajectory-aware 子集评测稳定，它会影响 coding agent 的日常回归测试和模型/策略迭代速度，尤其适合高成本 SWE benchmark。
- 局限 / 待验证点：论文仍依赖历史轨迹和特定 benchmark 分布；真实产品中的任务分布漂移、工具差异和失败归因还需要第三方验证。
- 研究成熟度：早期论文；声称代码和数据公开
- 可复现状态：论文原文可查；本次未复跑代码
- 原文链接：[arXiv:2609.01603v1](https://arxiv.org/abs/2609.01603v1)
- 权威解读：暂无
- 我的判断：这是本期最贴近 coding agent 工程效率的研究项。它把“评测很贵”这个实际问题转成可优化的轨迹选择问题。

### 2. CordisBench：动态 agent harness 的 component lifecycle 推理成为新评测对象

- 类型：benchmark
- 研究问题：当 agent 可以修改影响自身执行的软件组件时，本地插件变更会通过依赖、状态和 cleanup 顺序传播，模型是否能推理这些 lifecycle 影响仍不清楚。
- 核心思路：CordisBench 提供 1,200 个 lifecycle reasoning 问题，让模型识别受影响组件、预测 teardown 后状态、判断条件在不同顺序下是否成立，并选择可执行的 reconfiguration。论文报告模型在小系统上较好，但相关交互增加后可靠性下降。
- 为什么可能影响未来：agent runtime 越开放，插件、工具、MCP server 和工作流组件越像动态系统；只评估最终任务成功无法发现 lifecycle 误判。
- 局限 / 待验证点：这是 controlled formal setting；它和真实 IDE、CI、MCP server、browser sandbox 的差距还需要后续 benchmark 或实现衔接。
- 研究成熟度：早期 benchmark 论文
- 可复现状态：论文原文可查；本次未复跑
- 原文链接：[arXiv:2609.01600v1](https://arxiv.org/abs/2609.01600v1)
- 权威解读：暂无
- 我的判断：它和本期 Qwen / Gemini / Codex 的运行时治理线强相关。未来 agent 出错不一定是模型不会写代码，也可能是它误判了执行环境的组件状态。

### 3. Verbal Reinforcement Learning：把自然语言反馈分成 agent 生命周期里的三类作用

- 类型：论文
- 研究问题：自然语言正在成为改进 language agents 的反馈通道，但不同工作中语言反馈到底是在定义任务、指导测试时推理，还是更新模型参数，缺少统一分类。
- 核心思路：论文把 verbal feedback 按 agent lifecycle 中生效的位置和修改对象分成三类：language as grounding signal、language as deliberative feedback、language as learning signal。
- 为什么可能影响未来：这能帮助区分人类 review、自然语言奖励、skill 更新、prompt 规则和训练数据之间的作用边界，也能解释为什么 agent 产品开始记录 review reason、approval assessment 和执行证据。
- 局限 / 待验证点：这是综述 / taxonomy 取向，不能直接证明某种训练或产品路径更优；需要和真实 agent feedback loop 结合验证。
- 研究成熟度：早期综述论文
- 可复现状态：论文原文可查；非代码复现实验
- 原文链接：[arXiv:2609.01597v1](https://arxiv.org/abs/2609.01597v1)
- 权威解读：暂无
- 我的判断：它给本期社区里“agent factory”和“approval / review reason”提供了词汇：语言反馈不只是聊天记录，可能分别承担任务定义、在线纠偏和离线学习三种不同职能。
