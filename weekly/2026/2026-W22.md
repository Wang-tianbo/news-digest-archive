## 本周主线

- 本周最值得记住的，不是新的基础模型 headline，而是 `AI 编程代理进入运行时系统的深水区`。
- Anthropic 是本周最强样本。`Claude Code v2.1.152` 到 `v2.1.159` 连续覆盖 skills / slash commands、plugin marketplaces、MCP policy、dynamic workflows、Opus 4.8 effort、Auto mode on Bedrock / Vertex / Foundry、worktree 切换、tool 参数遥测和 background agents 修复。
- OpenAI 的 Codex 本周也给出明确组织接入信号。`0.134.0` 强化会话搜索、profile、MCP 并发和 schema 迁移提醒；`0.135.0` 则把 `doctor`、`/status`、named permission profiles、Python SDK sandbox presets 和非交互安装推到正式版。
- Qwen Code 是本周中国侧最连续、最可验证的公开工程线。从 v0.16.1 nightly 到 v0.16.2，再到 v0.17.0 和 2026-06-01 nightly，主线从本地上下文、并发、压缩、防失控，推进到 Feishu / Lark channel、computer-use、summary restoration compaction、memory pressure monitor 和 oversized history guard。
- Google 的 Gemini CLI 与 Gemini API 本周更多是平台和运行时治理信号：`Interactions API` 新 `steps` schema 默认切换、preview 模型生命周期节点、Gemini CLI v0.44 / v0.45 的 session、subagent、auth、routing、MCP hardening 和 PTY 稳定性修补。
- 综合看，本周不是“agent 会不会写代码”的问题，而是 `agent 能不能被组织接入、被多 agent 编排、长期稳定运行，并在上下文、权限、通道和工具协议上可控`。

## 本周评论与判断

- 基于本周样本，最重要的趋势是：`agent runtime governance` 已经从上周的观察主线进一步拆成几个具体胜负手：多 agent 编排、组织接入、插件 / 技能生态、worktree 隔离、长会话韧性和企业云运行模式。
- 本周加速最明显的是 Anthropic、OpenAI 和 Qwen。Anthropic 在产品面最完整，Claude Code 的 dynamic workflows 把多 agent 编排显性化；OpenAI 在 Codex 里继续补诊断、权限和 SDK / 安装可迁移性；Qwen 则用连续稳定版和 nightly 把中国公开 runtime 议题从“有节奏”推到“有差异化能力”。
- Google 本周不是最抢眼，但它的信号更像底座工作：Gemini API schema 迁移、Gemini CLI session / subagent / auth / routing 修补，都在为 agent-native API 和 CLI runtime 收紧边界。
- 本周需要修正的地方是：不能再把 Qwen Code 只写成“中国侧连续发版”。`v0.17.0` 的 Feishu / Lark、computer-use、压缩恢复和 PermissionDenied hooks 让它开始出现更明确的本土协作入口和自动化方向。
- 本周也要保持克制：Codex `0.136` alpha、Claude Code `v2.1.159` internal infrastructure、Gemini CLI patch / nightly 中的一些条目都是真实事实，但信息量不足时不应被强行拔高为趋势。

## 本周判断复盘

### 上周判断哪些被验证

- `竞争焦点从功能展示转向运行时和治理` 被进一步验证。Claude Code 的 dynamic workflows / worktree / plugin，Codex 的 doctor / permission profiles，Qwen Code 的 compaction / memory pressure，Gemini CLI 的 session / subagent 都是同一方向。
- `release cadence 本身是竞争力` 继续成立。高价值事实仍大量出现在 GitHub release notes、官方 changelog 和迁移文档，而不是发布会。
- `中国侧公开 agent runtime 主要看 Qwen Code` 被强化。Qwen Code 本周从 nightly、preview 到 stable 的承接非常清晰。

### 上周判断哪些被修正

- 上周的 `agent runtime governance` 需要细化，不再只是权限和后台任务，而是要拆成 `多 agent 编排`、`组织接入`、`长会话韧性`、`工具协议 / MCP` 和 `通道入口`。
- 对中国侧的判断需要上调一点。此前更像“Qwen Code 连续发版值得看”，本周应改成“Qwen Code 正在形成中国公开 agent runtime 的主要样本，但仍不能代表中国侧整体”。
- 对低信息量 release 的处理也需要更严格。alpha、patch、internal infrastructure 可以记录，但不能单独支撑强趋势判断。

### 本周新增判断

- `dynamic workflows` 值得进入长期观察。Claude Code 把多 agent 编排变成产品内置能力，下一步要看它是否能和权限、worktree、成本、审计闭环。
- `runtime resilience` 应从普通稳定性修补里升格出来。memory pressure、oversized history、provider error、settings corrupted warning 都是在解决长会话真实可靠性。
- `enterprise runtime mode` 开始出现。Claude Code Auto mode 扩展到 Bedrock / Vertex / Foundry，说明 agent 能力正在向企业云分发路径对齐。

## 本周最重要的 8 条更新

### 1. Claude Code 把 dynamic workflows 推到产品主线

- 发生了什么：
  Anthropic 在 [Claude Code v2.1.154](https://github.com/anthropics/claude-code/releases/tag/v2.1.154) 中加入 dynamic workflows，支持让 Claude 创建 workflow 并在后台跨多个 agents 编排工作，同时引入 Opus 4.8 high effort、fast mode、lean system prompt、后台 shell 和 streaming tool execution。
- 为什么重要：
  这让 Claude Code 从“终端里的强助手”进一步向“多 agent 工作台”演进。后续真正关键的是 dynamic workflows 是否能和权限、worktree、成本和审计能力形成闭环。
- 来源：
  [Claude Code Release - v2.1.154](https://github.com/anthropics/claude-code/releases/tag/v2.1.154)

### 2. Codex 0.135.0 强化诊断、权限、SDK 和非交互安装

- 发生了什么：
  OpenAI 在 [Codex rust-v0.135.0](https://github.com/openai/codex/releases/tag/rust-v0.135.0) 中加入更丰富的 `codex doctor`、远程 `/status` 信息、named permission profiles、Python SDK `Sandbox` presets 和 `CODEX_NON_INTERACTIVE=1` 安装模式。
- 为什么重要：
  这些都不是炫技功能，而是组织部署需要的基础能力：诊断环境、明确权限、让 SDK 调用更可控，并支持自动化安装。
- 来源：
  [Codex Release - rust-v0.135.0](https://github.com/openai/codex/releases/tag/rust-v0.135.0)

### 3. Qwen Code v0.17.0 把中国公开 agent runtime 推进一步

- 发生了什么：
  Qwen 在 [Qwen Code v0.17.0](https://github.com/QwenLM/qwen-code/releases/tag/v0.17.0) 中加入 Feishu / Lark channel adapter、skill-based RT optimization foundation、zero-config built-in computer-use、summary + restoration attachments compaction 和 AUTO classifier block hooks。
- 为什么重要：
  这让 Qwen Code 不只是“连续发版”，而是在国内协作入口、computer-use、压缩恢复和权限 hook 上形成更清晰的差异化方向。
