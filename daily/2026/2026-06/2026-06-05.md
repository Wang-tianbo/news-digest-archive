## 今日最重要的 5 条更新

### 1. OpenAI 发布 `Codex 0.137.0` 稳定版，组织治理、remote-control、plugin 与 multi-agent v2 同步推进

- 发生了什么：`openai/codex` 于 `2026-06-04 09:17` Asia/Shanghai 发布 [rust-v0.137.0](https://github.com/openai/codex/releases/tag/rust-v0.137.0)。主要新增包括 F13-F24 keybindings、searchable menus 粘贴、monthly credit limits、cloud-managed config bundles、EDU workspaces、app-server v2 remote-control pairing / grants list / revoke RPC、`codex plugin list --json`、cached remote catalog suggestions、hosted web / image tools 扩展、parallel standalone web searches、multi-agent v2 runtime choice 和更清晰的 spawned agents follow-up / metadata defaults。
- 为什么重要：这次稳定版把组织级治理、远程控制授权、插件生态、hosted tools 和 multi-agent 元数据一起推进。对团队使用而言，Codex 正在从“本地执行助手”走向“可被组织配置、审计、扩展和远程接管的 agent runtime”。
- 来源：
  [Codex Release - rust-v0.137.0](https://github.com/openai/codex/releases/tag/rust-v0.137.0)

### 2. GitHub Copilot Agent tasks REST API 进入 public preview，cloud agent 开始 API 化

- 发生了什么：GitHub 于 `2026-06-04` 发布 [Agent tasks REST API now available for Copilot Pro, Pro+, and Max](https://github.blog/changelog/2026-06-04-agent-tasks-rest-api-now-available-for-copilot-pro-pro-and-max)。Copilot Pro / Pro+ / Max 用户可以通过 Agent tasks REST API 以编程方式启动并跟踪 Copilot cloud agent tasks。官方示例包括跨仓库 fan-out refactors / migrations、从内部开发者门户一键初始化仓库、每周自动准备 release notes。
- 为什么重要：这是 Copilot cloud agent 从产品 UI 进入平台 API 的关键一步。API 化以后，agent 不再只是人在网页或 IDE 里点一次，而可以被内部工具、CI 流程和批量迁移脚本调度，GitHub 也就更接近企业工程自动化平台。
- 来源：
  [Agent tasks REST API now available for Copilot Pro, Pro+, and Max](https://github.blog/changelog/2026-06-04-agent-tasks-rest-api-now-available-for-copilot-pro-pro-and-max)

### 3. GitHub 把 Copilot cloud agent 接入 Actions 故障修复，并放开 1M context / configurable reasoning

- 发生了什么：GitHub 于 `2026-06-04` 发布 [Fix with Copilot for failing Actions now in Pro, Pro+, and Max](https://github.blog/changelog/2026-06-04-fix-with-copilot-for-failing-actions-now-in-pro-pro-and-max) 和 [Larger context windows and configurable reasoning levels for GitHub Copilot](https://github.blog/changelog/2026-06-04-larger-context-windows-and-configurable-reasoning-levels-for-github-copilot)。前者允许用户在 GitHub Actions job 失败时一键让 Copilot cloud agent 调查、推送修复并提醒 review；后者将 one-million-token context windows 和 configurable reasoning levels 推到 VS Code、Copilot CLI、GitHub Copilot app 等表面，并提示更大上下文或更高 reasoning 会消耗更多 AI credits。
- 为什么重要：Actions 故障修复让 agent 直接进入 CI 失败处理这个高频工程节点；1M context 和 reasoning 配置则给复杂代码库、架构和调试任务提供更强上下文能力。它们共同说明 Copilot 正在把 agent 从“回答问题”推向“处理软件生命周期里的重复性任务”。
- 来源：
  [Fix with Copilot for failing Actions now in Pro, Pro+, and Max](https://github.blog/changelog/2026-06-04-fix-with-copilot-for-failing-actions-now-in-pro-pro-and-max)
  [Larger context windows and configurable reasoning levels for GitHub Copilot](https://github.blog/changelog/2026-06-04-larger-context-windows-and-configurable-reasoning-levels-for-github-copilot)

### 4. Claude Code `v2.1.163` 补 managed version、plugin list、hooks feedback 与后台任务收尾

- 发生了什么：`anthropics/claude-code` 于 `2026-06-05 05:52` Asia/Shanghai 发布 [v2.1.163](https://github.com/anthropics/claude-code/releases/tag/v2.1.163)。主要变化包括 `requiredMinimumVersion` / `requiredMaximumVersion` managed settings、`/plugin list` 及 enabled / disabled 过滤、`/btw` 复制 raw markdown、Stop / SubagentStop hooks 可通过 `hookSpecificOutput.additionalContext` 给 Claude 反馈并继续 turn、skills 中 `\$` 转义、stdio MCP servers 在 `--resume` 时拿到与 hooks / Bash 相同的 `CLAUDE_CODE_SESSION_ID`，并修复 `claude -p` 后台命令不退出导致 hang、Bedrock / Vertex / Foundry 在 CI 下 API key 误报、TMPDIR regression、Windows OneDrive / read-only session-env、managed permission rules、新版本后 background sessions 丢任务等问题。
- 为什么重要：Claude Code 的企业化方向越来越具体：版本范围管控、插件列表、hooks 反馈、MCP session id、权限规则和后台任务收尾，都是组织级环境里会碰到的管控与可靠性问题。

  [Claude Code Release - v2.1.163](https://github.com/anthropics/claude-code/releases/tag/v2.1.163)
