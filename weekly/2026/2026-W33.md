## 本周主线

本周真正持续出现的主线，是 agent 竞争继续从“模型能做什么”下沉到“harness、插件、运行时、测试、模型路由和工程证据如何被组织治理”。OpenAI Agents SDK 连续补 MCP、RunState、sandbox acknowledgement 和 provider-neutral testing APIs；GitHub Copilot 把 memory、Ollama、MAI-Code、Gemini 3.7 Flash、Grok 4.6 和 agent app activity 放进多入口模型路由；Claude Code 连续推进 auto mode、远程控制、插件 marketplace、subagent fork、跨会话通信、gateway identity 和资源边界；Qwen Code 则围绕 review witness、autofix footprint、Desktop、Web Shell、Agent Plugins v1、ACP、OpenTelemetry 和 workspace trust 高频迭代。

第二条主线是“插件 / skill / harness”从产品细节升级为生态层。Agent Plugins 1.0 进入 GitHub / VS Code / Copilot 预览，并把 OpenAI、Microsoft、Cursor、GitHub、Vercel、Qwen 等放在同一协议叙事里；DeepSeek Harness 的 developer preview 把中国模型公司的公开竞争扩展到 plugin-first agent 工作台；Flue、Pydantic AI、OpenAI Agents SDK 和 Qwen Code 的样本也说明，agent 应用开发者关心的不再只是模型调用，而是 sessions、tools、skills、instructions、filesystem、sandbox、subagents、durability、observability 和 testing 的完整组合。

第三条主线是安全和可观测性进入更具体的工程边界。Claude Code auto mode 默认化让“减少确认疲劳是否会扩大风险”成为产品命题；Pydantic AI 本地 web agent 高危漏洞把 loopback server、浏览器请求、content type、CORS、凭据和工具权限拉到台前；reasoning trace 泄漏、Claude skills 同步加固、OpenAI sandbox credential acknowledgement、Qwen review witness、QuoteBench command-path failure 和 OpenAI testing APIs 共同说明，agent 安全已经不是抽象 prompt injection 问题，而是运行时、日志、UI、shell wrapper、插件供应链和测试路径的组合问题。

第四条主线是模型分发继续从“默认模型”转向“模型路由池”。OpenAI 预览 Ultrafast mode 与 GPT-5.6 builder guide，把速度 tier、Responses API 和 agent 成本工程包装成开发者默认栈；GitHub Copilot 在一周内接入 / 轮换 MAI-Code、Gemini 3.7 Flash、Grok 4.6，并把 Ollama 放进 JetBrains BYOK provider；Transformers、Ollama、vLLM 与 Muse Glimmer / Nemotron / Kimi / DeepSeek 等信号说明，本地模型和开放模型只有进入主流运行栈和企业策略界面后才有持续解释力。

研究前沿与产品事实高度同频。SHE 把 agent 安全更新对象从模型扩展到 harness artifact；SkillProx 和 TEPA 把 skills 与 memory lifecycle 变成 agent runtime 问题；VAKRA 把企业 agent 评测扩展到 API、检索和 tool-use policy；QuoteBench 和 Vero 分别把 coding agent 的可靠性推向命令路径定位和形式化可信；AMIE 与 factual recall 研究提示，多模态专业流程和企业知识场景也需要更细的评测与责任边界。

## 本周评论与判断

基于本周已归档样本的判断，`agent_runtime_governance` 仍是最高置信主线，但已经过大，需要拆出 `agent_harness`、`agent_plugin_standardization`、`deterministic_agent_testing` 和 `local_agent_security_boundary` 这些更具体的子线。现在的竞争对象不是“哪个 agent 会调工具”，而是谁能把工具、技能、插件、MCP / ACP、沙箱、会话、trace、测试、事件流和企业策略组合成可长期维护的工作系统。

第二个判断是，GitHub 当前在企业模型路由和组织控制面上继续领先。Copilot 的 agent app activity、memory、Ollama provider、MAI-Code 轮换、Gemini / Grok rollout、token spend、review effort 和 managed settings，说明 GitHub 正在把 Copilot 变成多模型、多 agent、多入口的管理平面。Anthropic 和 OpenAI 的优势分别在 Claude Code 的高频运行时细节和 OpenAI Agents SDK / Codex 的平台协议；Qwen 与 DeepSeek 则把中国侧竞争从模型侧推进到公开 runtime / harness 侧。

第三个判断是，中国公开 agent runtime 的证据强度上升。上周主要样本还是 Qwen Code；本周 DeepSeek Harness 以官方 repo、developer preview 和 plugin-first 架构加入后，`china_open_agent_runtime` 不再只是 Qwen 单线观察。仍需谨慎的是，DeepSeek Harness 的 GitHub 热度、媒体报道和 developer preview 不能直接等同于成熟生态；下周更重要的是插件质量、权限模型、沙箱、文档、breaking changes 和真实开发者复盘。

第四个判断是，agent eval 正在从“最终 solve rate”转向“过程可定位、约束可验证、成本可控制”。OpenAI testing APIs、VAKRA、QuoteBench、Vero、AV-AIVAT、SHE、TEPA 和 SkillProx 指向同一个变化：未来评价 agent 要看它在什么 harness 里运行、用了什么权限、如何处理记忆和技能、命令路径在哪里出错、是否能被 CI / replay 复现、是否能在政策约束下完成多源任务。

需要降权的叙事也更清晰。单个模型名称、单日 trending、nightly 频率、二手榜单和社区热帖只有在进入 Copilot / ChatGPT / Claude Code / Qwen Code / Ollama / vLLM / Transformers / Agents SDK 这类真实入口，或带来可复查评测、权限、成本、部署和组织采用证据时，才值得进入周度判断。

## 本周判断复盘

### 上周判断哪些被验证

- `agent_runtime_governance` 被继续强验证。Claude Code、Qwen Code、OpenAI Agents SDK、Pydantic AI、GitHub Copilot 和 DeepSeek Harness 全周都在补权限、沙箱、插件、session、memory、review、testing、trace、MCP / ACP、identity、resource limit 和 event stream。

- `workspace_agent_permissions` 被延续。Claude cross-session / subagent、Qwen Desktop / Web Shell / Local Control、Copilot JetBrains memory / Ollama、Pydantic local web UI 漏洞都说明 agent 正在进入更高权限和更复杂的本地 / IDE / 桌面工作区。
- `context_trust_for_agents` 被研究侧延续。Google factual recall、reasoning trace 安全、SHE、TEPA、VAKRA 和 QuoteBench 都在不同层面讨论上下文、记忆、轨迹、工具调用和证据链的可信边界。
- `china_open_agent_runtime` 被增强。Qwen Code 连续迭代之外，DeepSeek Harness 成为新的公开 repo 样本，Interconnects 对 GLM-5.3 的观察也加强了海外社区对中国模型公司工具链化的关注。

### 上周判断哪些被修正

- `agent_evaluation_methodology` 应进一步拆分。上周拆出 context trust、trajectory debugging 和 benchmark quality；本周还应加入 `deterministic_agent_testing`、`tool_use_policy_eval`、`command_path_reliability` 和 `verified_code_generation`。
- `workspace_runtime` 不能只写成办公系统 / 桌面入口。本周更强的风险面来自本地 web UI、loopback server、shell command transport、cross-session messaging 和 subagent context inheritance。
- `multi_model_agent_routing` 的权重上调。Copilot 一周内连续出现 MAI-Code、Gemini 3.7 Flash、Grok 4.6、Ollama BYOK 与 memory，说明模型路由已经从“可选模型”变成企业策略和开发者入口问题。
- `china_open_agent_runtime` 从观察项上调为升温候选，但仍不宜直接判定为成熟赛道。DeepSeek Harness 需要更多插件、安全、文档和第三方使用证据；Qwen Code 高频 release 也要看稳定版沉淀。

### 本周新增判断

- `agent_harness` 值得单独建候选台账。DeepSeek Harness、Flue、OpenAI Agents SDK testing、SHE、VAKRA、QuoteBench 和 Qwen / Claude 的 runtime 更新共同说明 harness 已经是 agent 能力、评测和安全的共同承载层。
- `agent_plugin_standardization` 值得候选升格。Agent Plugins 1.0 与 Qwen support Agent Plugins v1 让插件 / skill 资产可移植性第一次成为跨公司显性议题。
- `local_agent_security_boundary` 值得进入观察。Pydantic AI local web UI 漏洞、Claude skills 同步加固、reasoning trace 泄漏和 Qwen Web Shell / Desktop 都说明本地 agent 安全不能只靠模型侧策略。
- `agent_testing_and_replay` 值得进入观察。OpenAI Agents SDK testing APIs、Qwen review witness / ledger、Claude session replay / cross-session、Pydantic fallback tracing 与 QuoteBench 都把可测试性和可复盘性推到前台。
