## AI 研究前沿

### TurnSight：给 tool-integrated reasoning 做 turn-level hindsight self-distillation

- 类型：论文
- 研究问题：长链路工具调用任务里，只有 trajectory-level 结果很难给每一轮工具选择和中间状态做细粒度信用分配。
- 核心思路：论文提出 TurnSight，从执行后的 hindsight 构造多个 lookahead horizons 的 turn-level supervision，让模型在工具交互的每一轮获得更贴近实际状态的训练信号。
- 为什么可能影响未来：coding agent 和 research agent 的失败常常发生在中间工具选择，而不是最终回答格式。turn-level 训练如果有效，可能改善长任务里的早期纠错、工具选择和状态恢复。
- 局限 / 待验证点：当前是 arXiv 早期论文，本期未确认代码仓库或第三方复现；不同工具环境的泛化能力仍需验证。
- 研究成熟度：早期论文
- 可复现状态：论文公开；本期未确认代码仓库
- 原文链接：[arXiv:2608.04007](https://arxiv.org/abs/2608.04007)
- 权威解读：暂无
- 我的判断：这条研究与本期 agent runtime 修复形成互补：产品在补执行边界，研究在补长任务训练信号。

### Test-Time Scaling in Reasoning LLMs：把推理时扩展拆成可比较的 inference regimes

- 类型：论文
- 研究问题：test-time scaling 被用来描述单轨延长推理、多样本投票 / 验证、搜索未完成状态等不同算法，但很多报告只给预算和准确率，导致结果不可比。
- 核心思路：论文把 test-time scaling 形式化为 autoregressive model 隐式 prefix tree 上的 budgeted inference，并区分不同结构 regime、预算记账和失败模式。
- 为什么可能影响未来：agent、coding benchmark 和 reasoning model 的评测如果不说明 inference protocol，很容易把模型能力、采样策略和 verifier 贡献混在一起。更清晰的协议会影响后续模型报告和企业选型。
- 局限 / 待验证点：这是方法论 / 评测框架论文，不直接给出可部署产品；是否被主流 benchmark 采用还需要观察。
- 研究成熟度：早期论文
- 可复现状态：论文公开；本期未确认代码仓库
- 原文链接：[arXiv:2608.04001](https://arxiv.org/abs/2608.04001)
- 权威解读：暂无
- 我的判断：它值得跟踪，因为 2026 年 agent 评测越来越依赖推理预算、工具调用和 verifier；不把 protocol 写清楚，排行榜会越来越难解释。
