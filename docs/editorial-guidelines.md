# 日报写作规范

## 1. 时间窗

- 每篇日报覆盖前一日 09:00 到当日 09:00，时区为 Asia/Shanghai
- 标题和正文都使用绝对日期，例如 `2026-05-13`
- 如果严格时间窗内高价值更新偏少，可以补入最近几天仍在持续发酵的高价值官方更新，但必须明确写出补充范围
- 补充内容不能和前几日日报重复；如果没有新的高置信度信息，允许日报更短

## 2. 来源要求

- 优先使用官方来源
- 如果引用媒体报道，尽量补上一手来源
- 每条重要信息都保留可点击来源链接
- 本地 `AI 信号候选收件箱` 只作为候选线索入口，不能替代官方发布、论文原文、release、changelog 或原始项目链接
- 候选 review 里的采用理由和未采用理由都要尽量短而具体，方便后续周报、月报、年报复盘

## 3. 选题方法

优先选以下内容：

- 新模型、新产品、新能力发布
- 官方博客、研究、技术文章
- AI 编程代理的重要动作
- GitHub 上快速升温的 AI 开源项目
- 对商业格局、开发者工作流或技术路线有明显影响的事件

可以作为“外围高相关情报”补充的内容：

- 算力、半导体、HBM、先进制程、封装、服务器供给
- 云平台模型接入、数据中心、电力、推理容量与成本
- 监管、出口限制、AI 治理框架、安全与滥用应对
- 企业采用、组织变革、开发者生产率与岗位变化
- 医疗、教育、科研、政务等重点行业的高价值落地

可以作为“AI 圈博主”补充的内容：

- 中文互联网与全球范围内活跃 AI 博主、技术工作者、研究者、创业者及关键人物的公开输出
- 博客、RSS / Atom、Substack、GitHub、公众号公开页、长文、公开访谈中出现的 AI 线索、工具发现、社区信号、判断、困惑、分歧与方法论
- 中英文 AI 圈观点与社区信号源池中的媒体线索、开源工程生态、Agent 基础设施、推理平台、研究社区和安全治理源
- 对 AI 编程、模型竞争、产品形态、研究范式、组织采用有复盘价值的信息线索、观点判断、方法论或实践复盘
- 能够和当天事实样本互相印证、形成张力或提供新观察角度的观点与线索
- 暂不纳入 X-only 来源；如果 X API 不可用或账号只有 X 入口，在 `source_checks` 中标为 `blocked` 或 `partial`，不要写成 `miss`

可以作为“AI 研究前沿”补充的内容：

- AI 前沿论文、研究博客、benchmark、eval、开源实现和实验室动向
- 对模型能力、Agent、推理、训练、评测、数据、系统、具身智能等方向有未来预判价值的研究信号
- 作者、研究员、核心开发者、权威技术博主对论文或研究动向的高质量解读
- 能帮助判断技术路线、研究范式或未来产品能力变化的研究材料

降低优先级的内容：

- 重复转述的二手报道
- 没有原始来源的流言
- 只有流量、没有信息增量的话题
- 只有情绪表达、缺少可复盘判断的个人动态
- 没有原文链接、只有二手摘要的论文或研究动向
- 与 AI 主线没有清晰关系的泛科技新闻

## 4. 写作要求

- 先写结论，再写事实
- 每条信息尽量控制在 3 段以内
- 每篇报告必须包含单独的评论 / 判断模块
- 每篇日报建议包含一个简短的“结构化快照”，完整元数据可放在折叠区，便于周报、月报、年报做主题聚合，同时避免打断正文阅读
- 每条信息至少包含：
  - 发生了什么
  - 为什么重要
  - 来源链接
- 如果引用热度、stars、排名、版本发布等易变化信息，尽量附带时间点、发布日期或版本号
- 如果引用人物观点或资讯整理，必须明确标记条目类型，不能把个人判断或整理内容当作事实来源
- `AI 圈博主` 条目类型固定为：`信息线索`、`观点判断`、`方法论`、`实践复盘`
- 媒体、资讯整理、GitHub 项目动态和社区资源进入 `AI 圈博主` 时默认标为 `信息线索`，并尽量补官方发布、论文原文、release 或原始项目链接
- `AI 圈博主` 不要求每条都是强观点；只要可复查、AI 相关、相对近期、对社区体感 / 工具演进 / 方法论变化有信息增量，就可以写入
- 中英文扩展源每天合计要求选 5 条社区 / 观点信号：中文来源 2 条、英文来源 3 条；没有足够可复查信息增量时可以少于 5 条，但必须在 `source_checks` 说明缺口，不为凑数量机械填充
- 如果主窗口内命中不足 5 条，允许补入最近 7 天未写入过的公开输出；补入时必须标明发布日期或观察日期，并避免重复前几篇日报
- 同一来源可以连续入选；判断依据是是否有新的、可复查的信息增量，而不是人为轮换来源
- `AI 研究前沿` 条目类型固定为：`论文`、`研究博客`、`benchmark`、`eval`、`开源实现`、`实验室动向`
- `AI 研究前沿` 必须包含原文链接；权威解读可辅助理解，但不能替代原文
- `AI 研究前沿` 建议写明 `研究成熟度` 与 `可复现状态`，避免把早期论文、作者开源、第三方复现和生产落地区分不清
- 每篇日报应在 `结构化索引` 中记录 `source_checks`，说明主要来源组是否已巡检、巡检时间和结果
- 每篇日报建议在 `结构化索引` 中记录 `evidence_items`，为核心条目保留来源角色、证据类型、条目日期、快照时间和一手链接

`GitHub 热门项目` 额外口径：

- 这个栏目用于发现主线之外的新兴 AI 开源项目和关键基础设施，不用来重复收录 OpenAI、Anthropic Claude Code、GitHub Copilot 等已经在 `AI 新闻` / `AI 编程代理` 长期跟踪的官方主线项目
- 默认排除 OpenAI / Anthropic Claude Code / GitHub Copilot 及其官方仓库、SDK、CLI、文档仓库；这些项目如有重要更新，应写入 `AI 新闻`、`AI 编程代理` 或 `AI 圈博主` 的线索部分
- 尽量避免重复最近 7 天已经写过的热门项目；只有出现新的 release、架构变化、生态采用、star / trending 明显跃迁或生产使用证据时，才允许重复，并写明新增信息
- 如果当天没有足够新鲜且有信息增量的热门项目，可以省略本节，不要用主线官方项目占位

评论 / 判断模块建议回答：

- 今天真正值得记住的主线是什么
- 哪家公司或哪条产品线在加速
- 哪些变化可能只是噪声，哪些是趋势
- 接下来 1 周、1 个月值得继续跟踪什么

## 5. 推荐栏目

- `结构化快照`
- `主线判断`
- `今日评论与判断`
- `AI 新闻`
- `AI 圈博主`
- `AI 研究前沿`
- `GitHub 热门项目`
- `AI 外围情报观察`
- `值得继续跟踪`
- `结构化索引`
- `今日结构化结论`
- `参考来源`

## 6. 口径要求

- 事实和个人判断分开
- 评论必须建立在当天事实之上，不能写成空泛感想
- 评论段落最好显式标记为“基于本期样本的判断”或同等口径
- `AI 圈博主` 是常规巡检栏目；当天或最近 7 天未记录样本中出现有信息增量的公开线索、观点判断、方法论或实践复盘时应写入
- 人物观点和资讯整理不能替代官方发布、文档、changelog、Release、原始项目链接等事实来源，只能作为线索、思想信号或判断样本
- `AI 研究前沿` 是可选栏目；当天出现高价值论文或研究动向时可以写入，建议控制在 1-3 条
- 研究条目必须写出“为什么可能影响未来”和“局限 / 待验证点”，避免把论文摘要当成结论
- 如果信息存在不确定性，要明确写出“尚待验证”
- 如果某家公司当天没有高价值更新，不强行凑数
- 报告目标是高信噪比，不是信息全收录
- 外围情报只有在能清楚解释“它为什么会反作用于 AI 主线”时才写入日报，否则更适合留到周报 / 月报

元数据建议口径：

- `themes` 使用相对稳定、可复用的英文或拼音标签，例如 `agent_api`、`runtime_governance`、`multi_agent_workflow`
- `signals` 使用给人看的中文短语，例如 `组织级治理`、`移动端接管长任务`
- `opinion_sources` 用于记录进入日报的观点 / 线索来源人物、博客或长文来源；如果扩展巡检后没有可复查信息增量，写 `[]`
- `viewpoint_themes` 用于记录线索或观点主题，例如 `AI 编程方法论`、`研究范式争议`、`组织采用困惑`、`工具发现`
- `research_sources` 用于记录进入日报的论文、研究博客、benchmark、eval、开源实现或实验室动向来源；如果没有高价值研究信号，写 `[]`
- `research_themes` 用于记录研究主题，例如 `agent_evaluation`、`test_time_compute`、`world_model`
- `research_artifacts` 用于记录研究产物类型，例如 `paper`、`benchmark`、`eval`、`repo`、`research_blog`
- `research_interpretations` 用于记录权威解读来源；如果没有可用解读，写 `[]` 或 `none`
- `peripheral_themes` 用于记录外围情报归属，例如 `算力与半导体`、`政策与治理`、`企业采用`
- `source_checks` 用于记录本次运行实际巡检过的主要来源组，例如 `coding_agent_releases`、`china_model_officials`、`ai_blogger_core_radar`、`ai_blogger_free_opinion_pool`、`china_ai_media_signals`、`china_ai_engineering_radar`、`china_research_community`、`english_ai_engineering_radar`、`english_agent_infra_radar`、`english_inference_platforms`、`english_research_blogs`、`english_industry_analysis`、`english_safety_governance`、`research_frontier`
- `source_checks.result` 建议使用 `hit`、`miss`、`blocked`、`partial`；访问受限、入口不稳定或只完成部分巡检时用 `partial`
- `evidence_items` 用于记录核心条目的证据链，`source_role` 建议使用 `official`、`research`、`opinion`、`media`、`community`，`verification_status` 建议使用 `verified`、`partial`、`unverified`
- 候选收件箱中的 `adoption_reason` 用于记录为什么值得进入日报，`rejection_reason` 用于记录为什么暂不写入；未采用理由同样是长期认知资产
- 候选收件箱中的 `retrospective_status` 建议使用 `待验证`、`被强化`、`被削弱`、`被推翻`、`进入稳定现实`、`仍未明朗`
- `companies`、`products` 尽量用统一命名，避免同一对象出现多个写法
- `followups` 只记录短期可验证问题，不写空泛愿景
- `fact_confidence` 表示事实来源可靠性，建议使用 `high`、`medium`、`low`
- `signal_strength` 表示当天信号强弱，建议使用 `high`、`medium`、`low`

展示建议：

- 正文前部只放 4-6 行“结构化快照”，写给人看
- 完整 YAML 放到 `结构化索引` 折叠块里，写给后续机器聚合或人工复查
- 避免在正文最前面直接堆整块 YAML，影响进入主线的节奏
- `AI 圈博主` 默认每天写 5 条，中文来源 2 条、英文来源 3 条；只有在完成核心雷达、中文公开源、英文个人 / newsletter 源和工程社区源巡检后仍无足够可复查信息增量时，才允许少于 5 条或整段省略，并在结构化索引里写明缺口
- `AI 研究前沿` 不是每期必填；如果当天没有高价值论文或研究动向，正文整段省略，并在结构化索引里写 `research_sources: []`、`research_themes: []`、`research_artifacts: []` 和 `research_interpretations: []`
- `AI 外围情报观察` 不是每期必填；如果当天没有高置信度外围信号，正文整段省略，并在结构化索引里写 `peripheral_themes: []`

## 7. 文件规范

- 路径：`daily/YYYY/YYYY-MM/YYYY-MM-DD.md`
- 标题：`# AI 日报 - YYYY-MM-DD`
- commit message：`docs: add ai digest for YYYY-MM-DD`
- 周报路径：`weekly/YYYY/YYYY-Www.md`
- 月报路径：`monthly/YYYY/YYYY-MM.md`
- 年报路径：`yearly/YYYY/YYYY.md`

## 8. 长期建议

- 日报控制在 8-15 条重点信息
- 周末仍可生成日报，但允许内容更短
- 每周补一篇周报，重点聚合重复信号、判断修正和跨天趋势，而不是机械拼接日报
- 月报要强调阶段性格局变化、公司节奏和主题演进
- 年报要强调全年拐点、胜负手、方法论变化和持续判断修正

## 9. 周报方法

周报不是“把 7 天日报拼在一起”，而是要回答这些更高层问题：

- 这一周真正持续出现的主线是什么
- 哪些公司或产品在连续加速
- 哪些判断相比上周被强化、削弱或推翻
- 哪些事件只是单点噪声，哪些已经形成趋势
- 哪些议题值得进入长期跟踪台账

推荐周报写法：

- 先写本周主线，再写判断变化
- 用“延续 / 新增 / 修正”组织判断层
- 对重点主题写“连续性信号”，而不是只写单条新闻
- 为每个重要议题加一行状态：`升温 / 延续 / 转弱 / 待确认`
- 单独保留“本周议题台账流转”，明确哪些主题准备升格、哪些继续跟踪、哪些开始降权
- 如果本周外围变量开始明显反作用于 AI 主线，可单列“AI 外围情报观察”；如果没有高置信度外围变量，可整段省略
- 如果本地候选收件箱存在，可参考一周内重复出现的 `trend_key`、`观察中` 候选、采用 / 未采用理由和 `retrospective_status`，但仍以已归档日报和一手来源为主

## 10. 月报方法

月报要比周报再高一层，它不是总结“这个月发生了哪些事”，而是总结：

- 这个月哪些主线已经形成阶段性格局
- 哪些公司或产品开始建立稳定优势
- 哪些判断经过一个月后可以被确认或推翻
- 哪些噪声虽然很热，但没有留下持续增量

推荐月报写法：

- 先写阶段性结论，再写关键事件
- 强调“被验证的判断”和“被修正的判断”
- 对每条核心赛道补一行“阶段性变化”
- 用“本月议题台账”承接长期连续信号
- 单独保留“本月议题台账流转”，回答哪些议题正式升格、哪些进入稳定期、哪些开始转弱
- 月报应明显比周报更强调阶段性格局，而不是增加条目数量
- 月报可以使用候选收件箱中的后验复盘字段，区分哪些候选线索后来被事实强化、削弱、推翻或进入稳定现实

## 11. 长期议题台账方法

长期议题台账是日报、周报、月报之间的桥。

使用原则：

- 只为值得跨周、跨月追踪的问题建台账
- 台账要围绕“问题”建，而不是围绕单条新闻建
- 每次更新都要写“判断变化”和“下次重点看什么”
- 一个议题如果长期稳定存在，可以从 `升温` 转成 `进入稳定期`

年报建议补充：

- 年报不是把 12 个月结论拼起来，而是只保留那些真正改变全年格局的主线
- 年报应明确区分：哪些判断全年被验证、哪些判断全年被修正、哪些热点最后只是噪声
- 年报里的“外围情报”要比日报更克制，只保留那些真正塑造全年 AI 竞争环境的变量
