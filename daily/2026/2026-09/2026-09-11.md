### JarvisGUI：跨设备 GUI agent 评测开始模拟动态任务组合

- 类型：论文 / benchmark
- 研究问题：真实 GUI 任务经常跨手机、桌面和不同平台流转，但现有 GUI agent benchmark 多半停留在单设备、单任务路径。
- 核心思路：JarvisGUI 提出 cross-device GUI agent benchmark，关注中间状态转移、设备间协调和动态任务组合。
- 为什么可能影响未来：如果 agent 工作流要从单屏自动化进入真实个人或企业任务，跨设备状态管理会成为基础评测问题。
- 局限 / 待验证点：当前仍是论文摘要层信号；环境、任务集和第三方复现质量需要后续确认。
- 研究成熟度：早期论文

### IBIB：企业 AI 评测应按 serving route 而不是 model identifier 计分

- 类型：论文 / eval
- 研究问题：企业实际部署的是系统路由、精度、输出契约和 harness，而不是裸 model checkpoint；只按模型名评测会产生测量误差。
- 核心思路：IBIB 提出按 serving route 度量企业 AI 系统的协议，把权重、服务路径、精度和输出 contract 纳入同一个评测对象。
- 为什么可能影响未来：它直接击中企业 agent / LLM 平台采购和内部评测的问题：同名模型在不同 route 下可能不是同一个能力面。
- 局限 / 待验证点：协议价值需要真实企业系统和第三方 benchmark 采用来验证。
- 研究成熟度：早期论文
- 可复现状态：仅有论文原文；本次未复跑
- 原文链接：[arXiv:2609.10494v1](https://arxiv.org/abs/2609.10494v1)
- 权威解读：暂无
- 我的判断：这条和本仓库的 `multi_model_orchestration` 台账高度相关，应后续观察是否被模型路由、网关或企业评测工具引用。

### PACE：把感知延迟纳入 RAG 对话服务路由目标

- 类型：论文
- 研究问题：RAG 对话服务通常只在质量、成本或真实延迟之间做取舍，但用户感知到的首响应时间和 filler control 也会显著影响体验。
- 核心思路：PACE 将 perceived time-to-first-response 作为 QoE 目标，并把 cascading service routing、semantic caching 和 filler control 放进统一框架。
- 为什么可能影响未来：agent 产品的可用性越来越受 latency / cost / perceived responsiveness 约束，服务路由会成为产品体验的一部分。
- 局限 / 待验证点：是否能跨业务场景稳定收益，以及 filler 是否会引入误导性体验，需要真实产品实验验证。
- 研究成熟度：早期论文
- 可复现状态：仅有论文原文；本次未复跑
- 原文链接：[arXiv:2609.10372v1](https://arxiv.org/abs/2609.10372v1)
- 权威解读：暂无
- 我的判断：它把 `multi_model_orchestration` 从模型选择扩展到用户感知层，适合与 GitHub / Copilot / agent runtime 的批量治理线并行跟踪。
