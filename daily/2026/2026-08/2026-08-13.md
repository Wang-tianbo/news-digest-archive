#### 5. Pydantic AI v2.28.0 修复本地开发 web agent 高危漏洞，并加入 realtime speech-to-speech

- 事实：Pydantic AI 在 2026-08-12 发布 `v2.28.0` 和 `v1.107.4`，修复开发 web chat UI `Agent.to_web()` / `clai web` 的高危漏洞：旧 endpoint 没有检查请求 content type，开发者浏览器里打开的跨站页面可能在无 CORS preflight 情况下触发本地 agent 运行并用本地进程权限和凭据执行工具。新版本要求 `Content-Type: application/json`。同版还加入 `Agent.realtime()` speech-to-speech、Crusoe provider、browser WebRTC 和 server sideband 支持。

- 来源：[Pydantic AI v2.28.0](https://github.com/pydantic/pydantic-ai/releases/tag/v2.28.0)，[GHSA-h4xc-3qfq-jf93](https://github.com/pydantic/pydantic-ai/security/advisories/GHSA-h4xc-3qfq-jf93)

## AI 研究前沿

### 1. Google Research：factual recall 的瓶颈可能在“找回”而不只是“存储”

- 类型：研究博客
- 研究问题：语言模型事实性错误到底来自知识没有被参数化存进去，还是来自推理时无法从参数中稳定找回正确事实。
- 核心思路：Google Research 在 2026-08-12 发布 `Empty shelves or lost keys? Recall is the Bottleneck for Parametric Factuality`，把 parametric factuality 的问题拆成存储和 recall 两部分，并强调 recall bottleneck。
- 为什么可能影响未来：如果事实性瓶颈主要在 recall，改进方向就不只是增加数据或参数，也包括检索式解码、激活 / 表征访问、训练目标和评测方式。这会影响企业知识问答、agent planning 和长上下文系统如何组合参数知识与外部检索。
- 局限 / 待验证点：本期只核验到 Google Research 原文；需要进一步复查论文细节、实验任务、模型规模、可复现代码和是否适用于最新推理模型。
- 研究成熟度：研究博客 / 论文配套
- 可复现状态：仅有研究报告；本期未确认代码仓库
- 原文链接：[Google Research](https://research.google/blog/empty-shelves-or-lost-keys-recall-is-the-bottleneck-for-parametric-factuality/)
- 权威解读：Google Research 原文
- 我的判断：这条研究和企业 agent 主线有关。企业知识场景里，模型“知道”但无法可靠调出，和模型“不知道”会导致完全不同的工程策略。

### 2. Stealing Reasoning Traces：推理痕迹成为模型 API 的新安全边界

- 类型：论文
- 研究问题：前沿模型 API 中隐藏或半隐藏的 reasoning traces 是否可能被攻击者抽取，从而泄漏供应商内部推理过程或敏感中间信息。
- 核心思路：论文 `Stealing Reasoning Traces from Proprietary LLM APIs` 研究通过 API 行为抽取 proprietary LLM reasoning traces 的可行性，并被 Simon Willison 等工程社区关注。
- 为什么可能影响未来：随着 agent 平台暴露 reasoning effort、debug logs、trace、token breakdown 和可解释性界面，供应商需要重新划分“用户可见调试信息”和“模型私有推理信息”的边界。
- 局限 / 待验证点：本期采用公开论文与技术博客作为线索，尚需继续复查不同供应商 API 的适用性、修复状态和真实泄漏风险。
- 研究成熟度：早期论文
- 可复现状态：论文公开；本期未执行任何代码或攻击复现
- 原文链接：[arXiv:2608.09867](https://arxiv.org/abs/2608.09867)
- 权威解读：[Simon Willison](https://simonwillison.net/2026/Aug/11/stealing-reasoning-traces/#atom-everything)
- 我的判断：这条研究不应被理解成“不要暴露任何 trace”，而是提示 agent observability 必须分层：开发者调试、企业审计、用户解释和供应商内部推理不能混成一个日志流。

- 新出现了什么：Agent Plugins 1.0 把跨工具插件协议推到 public preview；Pydantic AI 漏洞把本地 agent web UI 安全明确暴露为现实攻击面。
- 被削弱了什么：把 agent 竞争只看成“谁的模型更强”的解释力继续下降；本期更关键的是协议、插件资产、企业案例、安全默认项和可观测运行时。
