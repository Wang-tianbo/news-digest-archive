## 今日最重要的 4 条更新

### 1. Claude Code `2.1.183` 加强 auto mode 安全，并修复 webhook / scheduled task approval 边界

- 发生了什么：`anthropics/claude-code` 于 `2026-06-19 09:20` Asia/Shanghai 发布 [v2.1.183](https://github.com/anthropics/claude-code/releases/tag/v2.1.183)。Release notes 显示，auto mode 现在会在用户没有明确要求丢弃本地工作时阻止 `git reset --hard`、`git checkout -- .`、`git clean -fd`、`git stash drop`；`git commit --amend` 也会在目标 commit 不是本会话 agent 创建时被阻止；`terraform destroy` / `pulumi destroy` / `cdk destroy` 需要用户指定具体 stack 才允许。该版本还新增 deprecated / auto-updated model warning、`attribution.sessionUrl` 设置、`/config --help`，并修复 scheduled task / webhook trigger 被当成键盘输入从而可能批准 pending action 的问题。
- 为什么重要：这是一条明确的 agent 安全治理信号。随着 Claude Code、Codex、Cursor 等工具进入 auto / remote / scheduled 模式，危险命令阻断、模型替换告警、自动触发来源分类、MCP auth-stub 暴露控制，都会直接影响企业是否允许 agent 长时间无人值守执行。
- 来源：
  [Claude Code Release - v2.1.183](https://github.com/anthropics/claude-code/releases/tag/v2.1.183)
  [Claude Agent SDK Python Release - v0.2.105](https://github.com/anthropics/claude-agent-sdk-python/releases/tag/v0.2.105)

### 2. OpenAI Agents SDK `0.17.6` 增加 pre-approval tool input guardrails

- 发生了什么：`openai/openai-agents-python` 于 `2026-06-19 14:03` Asia/Shanghai 发布 [v0.17.6](https://github.com/openai/openai-agents-python/releases/tag/v0.17.6)。最值得记录的新增项是 `pre-approval tool input guardrails`，同时加入 SDK-only custom data for tool outputs，并修正相关 JSON-compatible contract、handoff whitespace tool-name warnings 和 sandbox guide typo。
- 为什么重要：Agents SDK 正在把工具调用的治理点前移到 approval 之前。对复杂 agent workflow 来说，风险不只在工具执行后才出现，输入阶段就需要 schema、策略、审批和审计共同参与；custom output data 则有利于上层 workflow 保存可机器处理的工具结果。
- 来源：[OpenAI Agents SDK Python Release - v0.17.6](https://github.com/openai/openai-agents-python/releases/tag/v0.17.6)

### 3. GitHub Copilot usage metrics API 开始返回用户级每日 AI credits

- 发生了什么：GitHub 于 `2026-06-20 00:23` Asia/Shanghai 发布 [AI credits consumed per user now in the Copilot usage metrics API](https://github.blog/changelog/2026-06-19-ai-credits-consumed-per-user-now-in-the-copilot-usage-metrics-api/)。官方称 Copilot usage metrics API 现在会报告每个用户每天消耗了多少 AI credits，数据口径来自 usage-based billing API 的 AI credits consumption data。
- 为什么重要：这是 Copilot / agentic workflow 企业化的成本观测补丁。GitHub 已经在前几天连续补模型 surface、Opus 4.6 fast 下线、Copilot-authored PR 归因、AGENTS.md 和 issue MCP；本条把用量成本推进到用户级 API，有利于组织把 AI credits 与团队、项目、模型路由和 agent 任务关联起来。
- 来源：[GitHub Changelog - AI credits consumed per user now in the Copilot usage metrics API](https://github.blog/changelog/2026-06-19-ai-credits-consumed-per-user-now-in-the-copilot-usage-metrics-api/)

### 4. llama.cpp server 连续增强 agent 参数、router 通信和 token probability 性能

- 发生了什么：`ggml-org/llama.cpp` 在本窗口连续发布多个构建，其中 [b9726](https://github.com/ggml-org/llama.cpp/releases/tag/b9726) 增加 server `--agent` 参数并移除冗余 webui 命名兼容，[b9732](https://github.com/ggml-org/llama.cpp/releases/tag/b9732) 重构 child 到 router 的通信，[b9731](https://github.com/ggml-org/llama.cpp/releases/tag/b9731) 优化 `get_token_probabilities`，使用 partial sort 降低 top-n token 排序开销，[b9733](https://github.com/ggml-org/llama.cpp/releases/tag/b9733) 为 WebGPU 在 Vulkan + NVIDIA 上增加 F16 adapter toggles。
- 为什么重要：这不是模型发布，但与本地 / 私有推理 serving 的 agent 化有关。`--agent` 参数、router 通信和 token probability 性能，会影响本地 LLM server 作为 agent backend 时的接口语义、并发路由和低层响应成本。
