## 今日评论与判断

基于本期已确认样本，我的判断是：安全不再是 agent 产品的外部附录，而是核心能力本身。GPT-Red、Claude Code 的权限修复、Claude web_fetch 外泄演示、Pydantic AI 的 tool-call 历史修复，都指向同一件事：模型和工具链越会自动执行，越需要把攻击面、审批语义和历史一致性做成默认约束。

第二个判断是，coding agent 的竞争正在从“谁更聪明”转向“谁更能被恢复、迁移和托管”。Claude Code 修 wake-from-sleep credential store、idle web session MCP 重连和 subagent model override；Qwen Code 加 workspace path lock、extension management 和 silent shell liveness heartbeat；这些都不是演示功能，而是长任务运行时的可靠性补丁。

第三个判断是，本地 AI workspace 又开始升温。xAI Grok Build 的价值不只在 Grok 模型入口，而在它把本地文件、URL、粘贴板、命令和代码生成打包成一个可改造的 Mac 工具。它和 Ollama、Codex desktop、Claude Code desktop-hosted sessions 一起说明，本地端仍然是 agent 获取真实工作上下文的重要入口。

短期噪声是大量 alpha / nightly / canary release 的版本号；中期趋势是安全边界、工具调用历史、workspace 隔离、本地上下文和成本 / 恢复体验正在成为 agent 基础设施的真实分水岭。

- 研究成熟度：官方研究 / 安全系统说明。

### Claude web_fetch 外泄演示：agent 工具权限需要按“数据流”而不是“工具名”建模

- 发生了什么：2026-07-15，英文工程社区开始讨论一个 Claude `web_fetch` 外泄演示：攻击者通过提示注入让 Claude 把本地 / 对话上下文中的敏感内容带入外部 URL 请求。该信号来自公开技术博客与 Simon Willison 的转述，本期未将其作为官方事实源。

- 来源：[Simon Willison](https://simonwillison.net/)、[Ayush Paul 技术文章](https://www.ayush.digital/how-i-tricked-claude-into-leaking-your-deepest-darkest-secrets)
