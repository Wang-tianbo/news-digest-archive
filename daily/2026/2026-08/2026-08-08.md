## AI 研究前沿

### Learning When to Trust：外部上下文不应被简单全信或全拒

- 类型：论文
- 研究问题：LLM 接入检索、工具或外部信号后，如何在干净、误导、正确和无关上下文之间学会选择性信任，而不是为了抗误导而忽略所有上下文。
- 核心思路：论文提出 MIST benchmark 和 SC2W 指标，衡量 misleading signal 把 clean-correct 答案翻转成 wrong 的频率；再用 SCOPE 构造匹配偏好对，通过 DPO 在四类条件间平衡优化。
- 为什么可能影响未来：RAG、浏览器 agent、IDE agent 和企业知识库 agent 都依赖外部上下文。选择性信任比单纯“增强鲁棒性”更接近生产需求。
- 局限 / 待验证点：仍是早期论文；需要看 benchmark 是否被第三方采用，以及 SCOPE 是否能在闭源模型、真实 RAG 和多工具 agent 中复现。
- 研究成熟度：早期论文
- 可复现状态：本期仅核验 arXiv 原文，未做代码复现
- 原文链接：[arXiv:2608.06377](https://arxiv.org/abs/2608.06377)
- 权威解读：暂无
- 我的判断：这条值得进入长期台账，因为它把“上下文越多越好”的直觉改成“上下文可信度要可训练、可度量”。

### TRAJDEBUG：长任务 agent 调试从找错误扩展到追踪错误生命周期

- 类型：论文 / benchmark
- 研究问题：长轨迹 agent 失败时，如何定位最早导致最终失败的 critical error，而不是只看到一串局部错误。
- 核心思路：TrajDebug 用多粒度历史压缩和证据式错误识别追踪每个错误的 resolution status 与 terminal impact，并构造 TrajErrBench，包含来自 Tau2Bench 和 SWE-Bench Pro 的 486 条人工标注失败轨迹。
- 为什么可能影响未来：coding agent、browser agent 和 workflow agent 的问题不是“是否会出错”，而是出错后是否能定位、恢复和避免级联。调试 benchmark 会影响未来 agent observability 工具。
- 局限 / 待验证点：benchmark 规模仍有限；需要观察它是否能覆盖真实企业 repo、权限失败、外部 API 波动和多 agent 协作场景。
- 研究成熟度：早期论文 + benchmark 描述
- 可复现状态：本期仅核验 arXiv 原文，未做第三方复现
- 原文链接：[arXiv:2608.06346](https://arxiv.org/abs/2608.06346)
- 权威解读：暂无
- 我的判断：它与本期 Claude / Codex / GitHub 的 runtime 治理信号正好对应：agent 控制面如果没有轨迹级调试，就很难进入高风险生产流程。

### AV-AIVAT：用 anytime-valid stopping 降低 agent 对战评测成本

- 类型：论文 / eval
- 研究问题：在不完美信息游戏中比较两个 agent 强弱时，如何避免固定预算评测的浪费，同时不破坏置信水平。
- 核心思路：论文把 AIVAT 方差缩减与 continuously monitored Confidence Sequences 结合，形成 AV-AIVAT，用在线 value model 只从过去游戏学习，避免当前 game 自评分。
- 为什么可能影响未来：agent eval 成本会随着长任务、多模型、多环境快速上升。任何能降低评测样本量且保留统计保证的方法，都可能影响 benchmark 设计。
- 局限 / 待验证点：当前场景集中在 Heads-Up No-Limit Hold'em；需要验证是否能迁移到 coding、web、tool-use 和多 agent 协作评测。
- 研究成熟度：早期论文
- 可复现状态：本期仅核验 arXiv 原文，未做本地复现
- 原文链接：[arXiv:2608.06362](https://arxiv.org/abs/2608.06362)
- 权威解读：暂无
- 我的判断：它不直接改变产品，但对“agent eval 太贵”这个长期问题有方法论价值，适合作为后续评测成本台账候选。

- 事实：OpenAI 发布 critical cyber capabilities 说明，GitHub 同日把 Copilot agent activity、ROI、code review effort 推进到管理视图，Claude Code 和 Codex release 同步补 self-hosted runner、plugin、sandbox、secret redaction 和 managed authentication。

- 我的判断：未来模型能力强弱仍重要，但企业 agent 的主战场会越来越多地落在控制面：谁能解释、限制、度量、恢复和审计 agent。

## 值得继续跟踪

- GitHub Copilot usage metrics API 的 agent app activity 是否能细分到具体 partner agent、repo、PR、任务类型和成本。

## 判断变化

- 延续了什么：agent runtime 主线继续围绕权限、sandbox、session、review、plugin、cache、channel 和可观测性展开。
- 新出现了什么：企业管理层开始通过 Copilot ROI、agent activity、review effort 把 agent 价值显性化；Claude self-hosted runner 让企业执行位置成为新的竞争变量。
- 被削弱了什么：单纯模型发布或单个 UI 功能的解释力继续下降；没有控制面、评测面和恢复机制的 agent 能力更难进入高价值生产流程。
