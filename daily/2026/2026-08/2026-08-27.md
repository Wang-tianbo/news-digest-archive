## AI 研究前沿

### 1. OpenCompass v0.5.4：多模态评测、multi-round inference 和 LiteLLM gateway 进入评测框架

- 类型：benchmark / 开源实现
- 研究问题：大模型评测框架如何同时覆盖多模态、多轮指令跟随、API gateway 和更宽 benchmark 集。
- 核心思路：OpenCompass v0.5.4 集成 VLMEvalKit，支持原生多模态 dataset loading、OpenAI-compatible inference 和官方 VLMEvalKit metrics；`GenInferencer` 支持 multi-round inference，并加入 Multi-IF；同时引入 LiteLLM AI Gateway、TurboMind PPL API，以及 BuySideFinBench、ELBench、Inverse IFEval、CRUXEval、LongBench / MRCR V2 等配置。
- 为什么可能影响未来：模型发布越快，评测框架越需要跟上多模态、多轮、代码、长上下文和企业 API gateway 的真实形态。
- 局限 / 待验证点：release notes 证明框架能力更新，不等于所有新模型评测已经可比；具体榜单仍要看任务设置和可复现脚本。
- 研究成熟度：已发布开源评测框架版本
- 可复现状态：作者开源；本次未运行评测
- 原文链接：[OpenCompass v0.5.4](https://github.com/open-compass/opencompass/releases/tag/0.5.4)
- 权威解读：暂无
- 我的判断：这条最适合连接今天的新模型主题。Qwen / GLM / Kimi / DeepSeek 这类模型如果要被认真比较，评测工具必须先支持多模态、多轮和 gateway 场景。

### 2. SPO++：面向异步 agentic RL 的 stream-aligned policy optimization

- 类型：论文
- 研究问题：工具调用轨迹又长又不等长时，agentic RL 是否必须等待同 prompt 的 sibling rollouts 才能做 group-relative optimization。
- 核心思路：论文提出 SPO++，把 Single-stream Policy Optimization 扩展到异步 agentic RL，用 prompt-level value estimate 和流式更新降低等待 sibling rollouts 的成本。
- 为什么可能影响未来：如果成立，长工具调用 agent 的训练和在线优化可以更接近生产流量，而不是依赖整齐批次。
- 局限 / 待验证点：仍是早期论文，实际收益需要更多环境、工具任务和开源实现复现。
- 研究成熟度：早期论文
- 可复现状态：未验证
- 原文链接：[arXiv:2608.24870](https://arxiv.org/abs/2608.24870v1)
- 权威解读：暂无
- 我的判断：它与今天产品侧“background session / subagent / workflow”形成研究呼应：agent 越异步，训练和评测方法也越不能假设同步批处理。
