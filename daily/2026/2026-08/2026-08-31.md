## AI 研究前沿

### 1. Persona-Execution Separation：把 persona 演化和 audited execution 拆成两个 trust domains

- 类型：论文
- 研究问题：在有治理要求的组织里，LLM agent 的 persona / 指令 / 语气需要快速演化，但实际执行必须保持可追踪、可审计、可控，单一 trust domain 很难同时满足两者。
- 核心思路：论文提出 Persona-Execution Separation，把 persona 和 execution 放在不同 trust domains，通过 governed contract bridge 连接；persona 可以漂移，execution 保持 faceless and audited，跨域由 approval matrix、DLP 和 audit 约束。
- 为什么可能影响未来：它把今天产品侧看到的权限、审计、执行身份和人类反馈问题抽成架构模式，适合企业 digital employee、coding agent 和内网 automation 场景继续验证。
- 局限 / 待验证点：论文以 development / pilot case 和 mechanism check 为主，还缺少第三方复现和跨组织部署证据；实际 DLP / approval matrix 成本也未充分证明。
- 研究成熟度：早期论文
- 可复现状态：论文原文可查；本次未验证代码
- 原文链接：[arXiv:2608.27427v1](https://arxiv.org/abs/2608.27427v1)
- 权威解读：暂无
- 我的判断：它是本期最贴近 agent 产品化的研究项。若后续有真实实现或审计日志标准，它可能成为企业 agent 架构的参考词汇。

### 2. Beyond F1：AI 模型安全扫描器评测需要区分“判断准确”和“能否给出判断”

- 类型：eval
- 研究问题：静态扫描器用于识别模型 artifact 中可执行或不安全内容时，只看 F1 会掩盖 coverage、analysis completion 和 failure recovery 差异。
- 核心思路：论文用 170 个 Pickle / PyTorch focused artifacts、145 个 specimen families 的合成语料评估 ModelScan、ModelAudit 和 Fickling，并区分 non-N/A coverage、analysis completion、definitive security decisions、non-security findings 和 unsupported outcomes。
- 为什么可能影响未来：模型供应链安全会影响开源权重、企业模型仓库和 agent 下载执行链路；“扫描器没给出判断”本身就是安全事实，不能被 F1 指标吞掉。
- 局限 / 待验证点：语料是 controlled / synthetic corpus，和真实模型仓库里的压缩包、混合格式、恶意规避样本仍有差距；本次未复跑 benchmark。
- 研究成熟度：早期 eval 论文
- 可复现状态：论文原文可查；本次未验证代码
- 原文链接：[arXiv:2608.27424v1](https://arxiv.org/abs/2608.27424v1)
- 权威解读：暂无
- 我的判断：它对 AI 安全治理的启发很实用：企业不要只问 scanner 准不准，还要问它在哪些 artifact 上沉默、失败或无法给出安全结论。
