## AI 研究前沿

### Agent Hacks Agent：用 agentic autoresearch 为 Claude Code / Codex 做生产级红队

- 类型：论文
- 研究问题：production LLM agents 面对不可信文件、命令、workspace state 时，如何持续发现可复用的安全漏洞知识，而不是只记录一次性攻击 payload。
- 核心思路：论文提出 AHA，通过一个 agentic research environment 研究另一个生产 agent，形成 vulnerability hypothesis、falsifier、sandbox attack、trajectory reflection，并把确认结果沉淀为 Vulnerability Concept Graph。
- 为什么可能影响未来：如果这条路线成立，agent 安全评测会从静态 benchmark 走向“可复用漏洞概念库”，对 Codex、Claude Code、Copilot CLI 这类工具的 patch 验证更有价值。
- 局限 / 待验证点：目前仍是论文与实验框架，是否覆盖真实企业插件、MCP server、CI/CD 权限和复杂 repo 结构，还需要第三方复现。
- 研究成熟度：早期论文 / 有代码入口
- 可复现状态：作者声称代码可用，未做本仓库复现
- 原文链接：[Agent Hacks Agent: Autoresearch for Production-Agent Red-Teaming](https://arxiv.org/abs/2607.11698)
- 权威解读：暂无
- 我的判断：这是今天最贴近产品风险的研究信号；它和 GitHub 的 AI security detections、Claude Code 的 worktree isolation 修复在同一条线上。

### BackendForge：用真实后端服务合同评测 agentic 端到端代码生成

- 类型：benchmark / 论文
- 研究问题：coding agent 生成的后端服务是否真的能 build、deploy，并通过 OpenAPI 合同驱动的黑盒 HTTP 行为测试。
- 核心思路：BackendForge 构造 56 个 contract-defined backend generation tasks，要求 LLM 生成 Dockerized service，并通过 test agent 与 code agent 共演进 reference oracle；论文报告 GPT-5.5 在 base oracle 下成功率 55.4%，final oracle 下仅 28.6%。
- 为什么可能影响未来：它把 coding benchmark 从“修单个 bug / 写局部函数”推向“生成可部署服务”，更接近企业 backend 场景。
- 局限 / 待验证点：任务规模仍小，且 backend 服务类型、数据库状态、鉴权、异步任务等真实复杂度需要扩展。
- 研究成熟度：早期 benchmark
- 可复现状态：论文原文可查，未做本仓库复现
- 原文链接：[BackendForge: Benchmarking Agentic End-to-End Code Generation with Backend Services](https://arxiv.org/abs/2607.11042)
- 权威解读：暂无
- 我的判断：这是对 coding-agent 叙事的必要降温：模型可以写很多局部代码，但完整服务正确性仍是硬问题。
