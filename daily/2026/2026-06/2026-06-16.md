### 1. OpenAI Codex `0.140.0` 正式发布，补用量、迁移、删除、MCP 与凭据治理

- 发生了什么：`openai/codex` 于 `2026-06-16 05:06` Asia/Shanghai 发布 [rust-v0.140.0](https://github.com/openai/codex/releases/tag/rust-v0.140.0)。Release notes 新增 `/usage` 日 / 周 / 累计 token activity 视图，`/goal` 支持保留 oversized text、大块粘贴和图片附件，新增 `codex delete`、`/delete` 与 app-server `thread/delete` 的永久 session 删除，新增 `/import` 用于从 Claude Code 选择性导入 setup、project configuration 和 recent chats，`@` 统一打开 files / plugins / skills mentions menu，并增加 managed Amazon Bedrock API-key authentication 和 CLI / MCP OAuth 凭据加密本地存储。

## 官方博客 / 研究 / 发布

### xAI API Priority Processing

- 摘要：xAI 于 `2026-06-15` 在 release notes 中新增 Priority Processing，开发者可在 text、image、video inference endpoints 使用 `service_tier: "priority"` 请求更高调度优先级，响应会返回实际使用的 `service_tier`，且只在 priority 被使用时按 priority rates 计费。
- 值得关注点：这属于推理服务商业化分层，而非新模型能力。对 agent workload 来说，长任务、实时多媒体和高价值企业请求可能会越来越依赖显式优先级、成本和 SLA 口径。
- 来源：[xAI Release Notes - Priority Processing](https://docs.x.ai/developers/release-notes)

### Gemini API 模型 deprecation

- 摘要：Gemini API release notes 于 `2026-06-15` 公告 Imagen 4 / Gemini 3 Image 相关模型将在 `2026-08-17` shut down，Veo 2.0 / Veo 3.0 相关模型将在 `2026-06-30` shut down，并建议迁移到更新的 stable 或 preview endpoints。
- 值得关注点：这类 deprecation 对生产集成很重要，尤其是视频 / 图像生成工作流。它说明多模态模型 API 的生命周期会持续压迫开发者维护 model routing 和 fallback。
- 来源：[Gemini API Release Notes](https://ai.google.dev/gemini-api/docs/changelog)
