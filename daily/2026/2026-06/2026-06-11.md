## 今日最重要的 5 条更新

### 1. GitHub Copilot Chat 可以查看、搜索和追问云端 agent sessions

- 发生了什么：GitHub 于 `2026-06-10` 发布 changelog，称 Copilot Chat on web 与 Copilot cloud agent 的 handoff 改进：当用户从 Chat 创建 session、PR 或 repository deep research 时，Chat 会显示进行中的 session 状态；session 完成后，用户可以在 Chat 中追问该 session 或启动新的 session。GitHub 同时启用两个新工具：`Get agent logs` 用于把 cloud agent 在 PR 上的工作日志带入 Chat，`Session search` 用于按主题、标题或时间查找并总结过往 agent sessions。
- 为什么重要：这是 Copilot 从“触发 agent 任务”走向“查询 agent 历史与工作证据”的关键一步。对企业团队来说，agent 的可审计日志和可检索历史，可能比单次生成质量更影响是否敢把长任务交给云端 agent。
- 来源：[GitHub Changelog - Copilot Chat now sees your agent sessions](https://github.blog/changelog/2026-06-10-copilot-chat-now-sees-your-agent-sessions)

### 2. GitHub Copilot CLI 新增实验性 `/security-review`

- 发生了什么：GitHub 于 `2026-06-10` 宣布 Copilot CLI 新增 `/security-review` slash command，处于 public preview 的实验功能。它会分析本地代码变更，返回带 severity / confidence 的高置信安全发现和可执行修复建议，重点覆盖 injection、XSS、不安全数据处理、path traversal、弱加密等常见高影响漏洞类型。GitHub 明确说明它不依赖 GitHub code scanning、Dependabot 或 secret scanning，而是作为提交前的轻量补充。
- 为什么重要：安全审查正在进入 AI coding agent 的即时工作流。与传统扫描相比，CLI 内的 security-review 更接近“写代码时顺手问 agent 审一遍”，这会改变开发者对安全反馈的触发时机。
- 来源：[GitHub Changelog - Dedicated security review command now available in Copilot CLI](https://github.blog/changelog/2026-06-10-dedicated-security-review-command-now-available-in-copilot-cli)

### 3. Claude Code `2.1.172` 支持 nested sub-agents，并修复多项后台 agent / 模型治理问题

- 发生了什么：`anthropics/claude-code` 于 `2026-06-11 04:44` Asia/Shanghai 发布 [v2.1.172](https://github.com/anthropics/claude-code/releases/tag/v2.1.172)。Release note 显示，sub-agents 现在可以继续 spawn 自己的 sub-agents，最多 5 层；Amazon Bedrock 会在 `AWS_REGION` 未设置时按 AWS SDK precedence 从 `~/.aws` config 读取 region；`/plugin` marketplace 浏览加入 search bar；`claude_code.lines_of_code.count` OTEL metric 增加 `model` attribute。修复项覆盖 1M context 无 credits 的自动压缩、background agents 误读其他目录 `.mcp.json` trust / approvals、`availableModels` 限制未应用到 subagent model override / dispatch picker / advisor model、wildcard WebFetch / file permission rules、team memory stores recall、长会话性能和 idle CPU 等。
- 为什么重要：nested sub-agents 是多 agent 编排从概念走向产品能力的直接信号；同时，background agent 的 project settings、model allowlist、memory store 和权限规则修复说明 Anthropic 正在补真实团队环境里的治理边界。
- 来源：
  [Claude Code Release - v2.1.172](https://github.com/anthropics/claude-code/releases/tag/v2.1.172)
  [Claude Agent SDK Python Release - v0.2.96](https://github.com/anthropics/claude-agent-sdk-python/releases/tag/v0.2.96)

### 4. Cursor Bugbot 公布 6 月更新：更快、更便宜，并可在 push 前运行 `/review`

- 发生了什么：Cursor 于 `2026-06-10` 发布 Bugbot 更新，称平均 review 时间从约 5 分钟降到约 90 秒，平均每次 review 发现的 bug 从 `0.56` 提升到 `0.62`，成本约降低 `22%`；Blog 版本还写明 90% 的 Bugbot runs 会在 3 分钟内完成。Bugbot 现在由 Composer 2.5 驱动，并尊重组织的 model block lists；如果组织禁用 Composer 2.5，会回退到下一个最佳可用模型。Cursor 还新增 push 前 `/review`，可选择运行 Bugbot 和 Security Review，或直接用 `/review-bugbot`、`/review-security`，并能与 GitHub / GitLab 上的 Bugbot 结果同步，避免同一 diff 重复 review。
- 为什么重要：Cursor 给出了少见的 agent review 可量化指标，也把 code review 从 PR 后移到 push 前。这个方向会压缩“写完代码到发现问题”的反馈周期，并让 coding agent 更像持续审查工具，而不是一次性补全工具。
- 来源：
  [Cursor Changelog - Bugbot updates June 2026](https://www.cursor.com/changelog/bugbot-updates-june-2026)
  [Cursor Blog - Bugbot is now over 3x faster, 22% cheaper, and finds 10% more bugs](https://www.cursor.com/blog/bugbot-updates-june-2026)

### 5. Google 发布 DiffusionGemma，NVIDIA 同步优化本地 RTX 推理

- 发生了什么：Google DeepMind / Google 于 `2026-06` 发布 DiffusionGemma，Google 页面将其定位为 `4x faster text generation` 的模型；NVIDIA 于 `2026-06-10` 官方新闻称 Google DeepMind released DiffusionGemma，这是一个面向高速文本生成的 experimental open model，并已针对 NVIDIA GeForce RTX GPUs、NVIDIA RTX PRO platform 等进行优化。
