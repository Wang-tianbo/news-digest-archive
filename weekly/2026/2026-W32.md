## 本周主线

本周真正持续出现的主线不是某一个模型，而是 agent 进入组织流程后，运行时、权限、审计、度量和评测开始被一起产品化。Cursor 把 Google Workspace 插件接入 coding agent，GitHub Copilot 推出团队模型策略、managed settings、cloud agent reasoning level、评论触发自动化、agent app activity、ROI 和 code review effort，Anthropic Claude Code 连续修 sandbox / credential masking / permission bypass 并加入 self-hosted runner，OpenAI Codex 发布 portable Agent Plugins，Qwen Code 则从 Web Shell、Desktop、review verifier、Goal、Live Host、memory、DingTalk / Feishu channel 到 compression cache 连续加厚。

模型层仍有重要信号，但影响力取决于是否进入真实入口。OpenAI 调整 GPT-5.6 Sol / Luna 在 ChatGPT 中的可用性，Kimi K3 进入 GitHub Copilot 但 rollout 因 GitHub Actions incident 暂停，Meta 发布 Muse Code / Muse Spark 1.2 并强调 long-horizon coding 与 toolset co-training，Qwen3.8-Max 和 MiniMax H3 则显示中国模型公司继续把模型发布与 coding agent、视频工作流和开源生态绑定。

安全和治理不是外围背景，而是本周 agent 主线的一部分。OpenAI / UK AISI cyber eval 事件、OpenAI critical cyber capabilities、Anthropic biology safeguards、Claude Code 的权限绕过修复、Codex 的 secret redaction / plugin isolation、GitHub 的 agent activity metrics，都在说明 agent 被放进高权限环境后，厂商必须能解释、限制、度量、恢复和复盘。

研究前沿也与产品事实同频。SWE-Touch 把 coding agent 放进共享可变工作区，Magnet 关注跨会话能力积累滥用，Learning When to Trust 研究外部上下文可信度，TRAJDEBUG 追踪长任务错误生命周期，Benchmarking the Benchmarks 反过来评估 agent benchmark 质量。研究侧正在从“最终答案对不对”转向“过程、上下文、评测协议和错误链是否可信”。

## 本周评论与判断

基于本周已存档样本的判断，`agent_runtime_governance` 已经从工具细节变成企业 agent 的主战场。权限、sandbox、credential masking、worktree、self-hosted runner、plugin catalog、review evidence、ROI、usage metrics、reasoning effort、tool visibility、cancellation、memory 和 channel context 不是散点功能，而是同一个控制面里的组件。

第二个判断是，workspace agent 正在从“IDE 里的上下文增强”升级为“组织系统接管”。Cursor 接入 Google Workspace，OpenAI 把 ChatGPT Work / Codex / 教育放在同一组更新里，Qwen Code 和 Cherry Studio 推进桌面工作台，Claude / Codex / Copilot / Gemini / Qwen 都在补多会话、历史、恢复和跨会话能力。下一阶段要看的不是插件数量，而是权限粒度、管理员策略、审计日志、撤销 / dry-run、数据边界和人类确认流程。

第三个判断是，模型发布的解释力越来越依赖分发路径。Kimi K3 进入 Copilot 是强信号，因为它把中文开权重模型放到主流开发者入口；Meta Muse Code 是强信号，因为它把模型与 coding harness 一起训练和发布；MiniMax H3 是强信号，因为它把视频模型、skills、API、Hugging Face / ModelScope 和 workflow 放在一套系统叙事里。单独模型名或榜单分数的权重继续下降。

第四个判断是，agent eval 正在进入第二阶段。W30 关注 eval harness security，本周进一步扩展到 shared workspace、cross-session misuse、context trust、trajectory debugging、benchmark quality 和 eval cost。未来评价 agent 不能只看 solve rate，还要说明工作区是否共享、外部上下文是否误导、错误何时发生、benchmark 本身是否可靠、推理 / 工具预算如何记账。

- `workspace_runtime` 不应只理解为本地工作区或 IDE 上下文。本周它应拆成三条子线：办公系统连接器、桌面 / Web Shell agent 工作台、企业团队控制面。

- 当前状态：待确认 / 候选观察
- 下周观察点：
  TRAJDEBUG 是否开源；Claude / Codex / Copilot / Qwen 是否暴露更标准化的 trace 和 replay 数据。
