## AI 研究前沿

### SWE-Touch：把 coding agent benchmark 放进会被用户改代码的共享工作区

- 类型：论文
- 研究问题：真实软件开发里，用户可能在 agent 执行任务时查看和修改代码；现有 repository-level benchmark 往往假设 agent 独自工作，难以测 agent 对共享工作区变化的感知能力。
- 核心思路：论文提出 SWE-Touch，用 validated Counter-Edits 在 agent 执行到相关代码区域时注入和任务冲突但看似合理的用户修改，并在 SWE-bench Verified、SWE-Bench Pro、DeepSWE 等任务上评估。
- 为什么可能影响未来：coding agent 进入团队后，最常见的真实场景不是“agent 独占仓库”，而是用户、CI、review、其他 agent 同时改变工作区。这个 benchmark 把协作干扰纳入评测，方向比单纯解题率更贴近生产。
- 局限 / 待验证点：当前是 arXiv 论文，本期未确认官方代码仓库或第三方复现；Counter-Edit 构造能否覆盖真实团队修改仍需验证。
- 研究成熟度：早期论文
- 可复现状态：论文公开；本期未确认代码仓库
- 原文链接：[arXiv:2608.02499](https://arxiv.org/abs/2608.02499)
- 权威解读：暂无
- 我的判断：这条研究应进入 coding-agent 长期台账，因为它直接挑战“agent 在单人沙盒里跑得好就能进团队”的假设。

### Magnet：用 capability accumulation 识别跨会话 AI 滥用

- 类型：论文
- 研究问题：攻击者可以把有害目标拆成多个看似无害的 session，让单会话检测难以看出整体意图；如何识别跨会话能力积累。
- 核心思路：论文提出 Magnet，把每个交互产出的 artifact 或工具结果视为可组合 capability，并关注这些 capability 在多个 session 中如何累积成有害整体。
- 为什么可能影响未来：当平台开始支持多 agent、多任务、评论触发自动化和长期 memory 时，安全系统不能只看单次 prompt 或单会话上下文。
- 局限 / 待验证点：仍是早期研究；跨平台身份、隐私边界、误报率和企业日志保留策略都会影响实际可部署性。
- 研究成熟度：早期论文
- 可复现状态：论文公开；本期未确认代码仓库
- 原文链接：[arXiv:2608.02518](https://arxiv.org/abs/2608.02518)
- 权威解读：暂无
- 我的判断：这条研究与 OpenAI / UK AISI cyber eval incident 和 Claude / Qwen 的 tool guardrail 修复形成闭环：agent 安全的下一层问题是跨会话、跨工具、跨任务的意图重组。
