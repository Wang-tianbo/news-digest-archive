基于本期已确认样本，我的判断是：agent 的竞争正在被“长任务治理”重新定义。OpenAI 的安全文章讨论模型在长任务中保持目标、接受监控和避免隐性动机的问题；Claude Code、Copilot CLI、Qwen Code、Kimi Code 的 release 则把同一个问题落到文件系统隔离、OS sandbox、worktree、hook、自恢复和 web server 生命周期上。

## AI 研究前沿

### OpenAI long-horizon models safety：长任务模型需要过程级安全评估

- 类型：研究博客 / 实验室动向
- 研究问题：当模型能执行更长、更复杂、跨工具和跨会话的任务时，如何评估它是否保持用户目标、接受合理监控，并避免隐性动机或不当策略。
- 核心思路：OpenAI 把 long-horizon models 的安全拆成模型行为、任务过程、监控、评估和部署约束等层面，而不是只看最终回答是否有害。
- 为什么可能影响未来：这会直接影响 coding agent、research agent、企业自动化 agent 的发布评估和产品设计。只在任务结束后看结果不足以发现长任务过程中的权限越界、目标漂移和监控规避。
- 局限 / 待验证点：文章是官方安全框架说明，不是完整可复现实验；具体 eval 任务集、阈值、失败样本和第三方审计仍需后续公开材料。
- 研究成熟度：官方研究 / 安全博客。
- 可复现状态：公开文章可复查；未确认完整 benchmark 或代码开源。
- 原文链接：[OpenAI - Safety and alignment in an era of long-horizon models](https://openai.com/index/safety-alignment-long-horizon-models/)
- 权威解读：暂无优于原文的一手解读纳入。
- 我的判断：这条研究信号与本期所有 agent release 相互印证。长任务安全不是抽象伦理问题，而会落到 sandbox、worktree、hook、成本池、MCP 生命周期和审计日志这些工程细节上。
